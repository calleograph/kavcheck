# KAV Checker — текущее состояние проекта

KAV Checker — самостоятельный веб-продукт для аудита и отчётности по данным Kaspersky Security Center (KSC). Он читает базы серверов администрирования KSC на Microsoft SQL Server и хранит собственные настройки, историю, расчёты и задания в PostgreSQL. Устанавливается через Docker Compose. Аудиторы и системные администраторы работают с данными нескольких источников с учётом прав на каждый источник.

## Архитектура

| Сервис | Технология | Ответственность |
|---|---|---|
| `web` | nginx unprivileged, React 19, TypeScript, Vite | SPA, прокси `/api/`, CSP |
| `backend` | Python 3.12, FastAPI, SQLAlchemy async, Alembic | API, аутентификация, запросы к источникам, постановка заданий |
| `worker` | образ backend, `app.worker` | отчёты, каталог ПО, загрузки и расчёты VDB и EOL, зоны, BI, аудит AD, инвентаризация |
| `pentest` | образ backend, `app.pentest.worker` | выполнение сетевых заданий в разрешённой области |
| `postgres` | PostgreSQL 16 | внутренняя база приложения |

Шаблоны запросов к KSC находятся в `backend/app/ksc/queries.py`. Параметры передаются через pymssql, каждый запрос проверяет `guard.py`, доступ идёт через общий реестр клиентов с ограничением числа соединений, времени и объёма выборки. При отсутствии объекта KSC API сообщает, какая функция недоступна. Миграции Alembic относятся к PostgreSQL. В рабочей копии текущая ревизия — `0040_inventory_geo`. См. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и [карту схемы KSC](docs/ksc/KNOWLEDGE_MAP.md).

Тяжёлые расчёты выполняются в фоне порциями под ограничителем ресурсов и арендой задания. Карточки, отчёты и зоны используют подготовленные результаты анализа внешних уязвимостей. XLSX формируется потоково. См. [docs/JOBS.md](docs/JOBS.md), [docs/PERFORMANCE.md](docs/PERFORMANCE.md) и [docs/HOST_REPORT.md](docs/HOST_REPORT.md).

## Код, настройки и эксплуатация

- `backend/app/main.py` собирает FastAPI, `api/` содержит маршруты, `models.py` — основную схему данных, `reports/` — построители и экспорт, `services/` — общие службы, `backend/migrations/versions/` — миграции.
- `frontend/src/App.tsx` задаёт оболочку приложения, `navModel.ts` — навигацию и быстрый доступ, `api.ts` — клиент API. Общие фильтры, таблицы и панели находятся в `components/`. Темы `night`, `glass`, `grove` и `aurora` используют токены `styles.css`. См. [docs/UI.md](docs/UI.md).
- Локальные учётные записи и LDAPS поддерживают TOTP. Роли в порядке расширения полномочий — `zone`, `viewer`, `analyst`, `security`, `admin`. Права на источник проверяет сервер. Доступ ответственного ограничен назначенными зонами. См. [docs/ADMIN_GUIDE.md](docs/ADMIN_GUIDE.md) и [docs/LDAP.md](docs/LDAP.md).
- Параметры установки описаны в `.env.example`, в том числе `APP_PUBLIC_URL`, `DATA_ROOT`, `POSTGRES_*`, `APP_MASTER_KEY`, `IMAGE_REPO`, `IMAGE_TAG` и ограничения ресурсов. Секреты хранятся в локальном `.env` или зашифрованными в базе. Рабочие данные в репозиторий не входят. См. [docs/INSTALL.md](docs/INSTALL.md).
- Помощник `scripts/updater.sh` работает на хосте через каталог `DATA_ROOT/updater`. Администратор запускает обновление из интерфейса. Скрипты проверяют установку, создают резервную копию и выполняют миграции. При сбое предусмотрен откат. См. [docs/UPDATE_AND_BACKUP.md](docs/UPDATE_AND_BACKUP.md).

## Проверка

- Backend: `cd backend && .venv/bin/python -m pytest -q`. Базовый набор использует SQLite и подставной KSC. Интеграционные тесты принимают синтетический SQL Server из `tests/ksc_synthetic/`.
- Frontend: `cd frontend && npm test && npm run build`.
- В корне: `python3 scripts/check_private_data.py` и `ALLOW_UNRELEASED=1 ./scripts/release.sh check`.
- Локальная разработка, синтетические источники и правила изменений описаны в [docs/DEVELOPER.md](docs/DEVELOPER.md) и [AGENTS.md](AGENTS.md).

## Известные ограничения и открытые проверки

- KSC хранит наблюдения о пользователях. Признак «сейчас в системе» берётся из актуальной записи KSC, время входа и выхода ограничивается интервалом между опросами. См. [docs/DEVICES.md](docs/DEVICES.md).
- Вывод о смене или сбросе пароля зависит от полноты журналов контроллеров домена. Живой поиск на вкладке каталога AD в аудите 0.38.0 оставался открытой проверкой на целевой установке. См. [docs/ADAUDIT.md](docs/ADAUDIT.md).
- Этапы учётного контура, инвентаризации, склада и инфраструктуры выпущены. Отложенные идеи по остальным разделам собраны в [docs/BACKLOG.md](docs/BACKLOG.md), этапы инвентаризации — в [docs/INVENTORY.md](docs/INVENTORY.md).
