# Инструкции для ИИ-агентов и новых разработчиков

KAV Checker — самостоятельный продукт. Для работы с ним не нужны никакие внешние проекты: всё, что требуется знать о структуре Kaspersky Security Center, собрано в `docs/ksc/`.

## Устройство (кратко)

- `backend/app` — FastAPI. `ksc/` — адаптер базы KSC (драйвер pymssql, защита запросов, SQL-шаблоны, диагностика, версии, группировка); `reports/` — построитель отчётов и воркер; `api/` — маршруты; `auth/` — сессии, роли, LDAP; `services/` — настройки, аудит, обновления.
- `frontend/src` — React + TypeScript, без UI-библиотек; стили в `styles.css`.
- `deployment/compose.yml` — postgres, backend, worker, web. `scripts/` — установка, обновление, откат, резервные копии, помощник обновлений.
- `docs/` — для администраторов и разработчиков; `docs/ksc/` — карта знаний KSC.

Подробно: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/DEVELOPER.md](docs/DEVELOPER.md).

## Правила работы с базами KSC (обязательно)

1. **Только чтение.** Никаких INSERT/UPDATE/DELETE/DDL/EXEC. Каждый SQL проходит `app/ksc/guard.py`; новые запросы — только шаблонами в `app/ksc/queries.py` с параметрами pymssql (`%(name)s`). Строки от пользователя в SQL не подставляются; списки идентификаторов — через `queries.ids_list` (только int). Текстовый поиск (`LIKE`) — только через `app/search.py`: `mssql_like(текст, mode)` для KSC, `column_like`/`any_of` для внутренней базы, `matcher`/`any_field` для списков в памяти; `*` — любое число символов (правила и пределы — там же).
2. **Ограничения:** постраничная выдача (`OFFSET … FETCH`), `max_rows`, тайм-аут запроса, семафор одновременных запросов на источник. Тяжёлое — только фоновым отчётом.
3. **Не изменять структуру базы KSC** и не «чинить» её. Если объекта нет — функция сообщает о несовместимости (`app/ksc/schema.py`, `FEATURE_OBJECTS`).
4. **Даты KSC — UTC.** Активность считается по `tmLastNagentConnected`. `nIp`: первый октет в старшем байте. Действующие установки — `bDeleted = 0`. Версии сравниваются алгоритмом dpkg (`app/ksc/versions.py`), не строками.
5. **Миграции** (Alembic) относятся только к внутренней базе KAV Checker.

## Конфиденциальность

- В репозиторий не попадают имена организаций, компьютеров, домены, IP-адреса, учётные записи, дампы и отчёты. Примеры — `example.local`, адреса из 192.0.2.0/24. Проверка: `python3 scripts/check_private_data.py` (в CI обязательна; `--history` — по всей истории git).
- Секреты только в `.env` (вне git) и в базе в зашифрованном виде (`APP_MASTER_KEY`). Пароли не возвращаются через API и не пишутся в журналы (`logging_setup.scrub`).

## Как добавить

- **Новая страница с данными:** фильтры — только `FilterBar` (`components/FilterBar.tsx`), число, раскрывающееся в список устройств, — `CountButton` + `HostsDrawer`, отчёт — `ReportButton` → `QuickReportPanel` с параметрами текущего представления (принцип «любые данные на странице можно выгрузить в отчёт», см. [docs/UI.md](docs/UI.md)); подробный экспорт не использует усечённые представления («+N»).
- **Главная и лицензии:** показатели — `backend/app/overview/calc.py` (один предикат на число и список), `api/overview.py`, срезы — `overview/snapshots.py`; лицензии — `ksc/licenses.py` (столбцы по каталогу, ключи не хранятся), `licensing/`. Подробно: [docs/DASHBOARD.md](docs/DASHBOARD.md).
- **CVE Hunt:** `backend/app/hunt/` (`criteria.py` — CVE и продукты, `kb.py` — порты и признаки версии, `scope.py` — область, `ksc.py`/`enrich.py` — данные KSC, `match.py` — сопоставление в сканере, `results.py` — объединение, список, сравнение, `service.py` — создание задания), `api/hunt.py`, отчёт `reports/quick_hunt.py` + `hunt_html.py`, страница `HuntPage`. Задание — `pt_jobs` с профилем `hunt`, исполняет сканер Pentest; своей базы CVE, очереди и генератора отчётов не создавать. Подробно: [docs/HUNT.md](docs/HUNT.md).
- **Pentest:** `backend/app/pentest/` (`targets.py` — область разрешений, `nmap.py` — запуск без shell и разбор XML, `scanner.py` — конвейер и восстановление, `analyze.py` — сопоставление и уверенность, `applic.py` — роль компонента, платформа, пакеты Debian, `nse.py` — каталог и оценка скриптов NSE, `nuclei.py` / `policy.py` / `engine.py` — Nuclei, политика шаблонов, шаблоны и каталог `pt_checks`, `kb.py` — тексты собственных проверок, `oval.py`), `api/pentest.py`, отчёт `reports/quick_pentest.py` (+ `pentest_doc.py`, `pentest_html.py`, `pentest_pdf.py`; уровни критичности — `levels`, по умолчанию только критические), страницы `pages/pentest/`. Nmap и Nuclei запускает только сканер (контейнер `pentest`; Nuclei — с фиксированными аргументами, только разрешённые подписанные шаблоны, stdin закрыт); вторая база CVE не создаётся; версия без ответа сервиса не подставляется; «подтверждено» — только проверкой/OVAL. Подробно: [docs/PENTEST.md](docs/PENTEST.md).
- **Раскрывающиеся строки таблиц:** `components/ExpandRow.tsx` (`useExpanded`, `ExpandTh/ExpandCell/ExpandedRow`, `XGrid`, `SafeText`); в виртуализированных списках — `VirtualRows group`.
- **Новый отчёт:** вид в `reports/builder.py` (функция `build_<kind>` → `(rows, summary)`), колонки в `builder.*_COLUMNS`, ветка в `reports/runner.py`, схема параметров в `api/schemas.py`, тип в `frontend/src/api.ts` и форма в `pages/ReportsPage.tsx`.
- **Новый модуль аудита** (лицензии, сравнение периодов…): SQL-шаблоны в `ksc/queries.py` + объекты в `FEATURE_OBJECTS`, сервис в `ksc/<module>.py`, маршрут в `api/` (образец — `api/protection.py`: кэш, глобальный фильтр активности, `unsupported`), страница в `pages/` и пункт в `NAV`. Используйте общие компоненты: `current_source`, роли (`require_user/analyst/admin`), `write_audit`, `Journal`, `Pager`, `Fetched`, `HiddenNote`.
- **Зоны ответственности, рассылки, решения по уязвимостям:** `backend/app/zones/` (`match.py` — принадлежность компьютеров, `csv_io.py`, `dataset.py` — запись «компьютер × проблемы», `snapshot.py` — потоковый расчёт подготовленных данных зон (worker), `zread.py` — чтение их агрегатами SQL, `zjobs.py` — очередь заданий и ночное расписание, `report.py` — отчёт зоны, `triage.py`, `mailer.py` — очередь и расписания), `api/zones.py`, страницы `ZonesPage` и `admin/{Zones,Mail,Org}Admin`; порядок таблиц во всех отчётах — `reports/layout.py`. Подробно: [docs/ZONES.md](docs/ZONES.md), [docs/ZONE_CACHE.md](docs/ZONE_CACHE.md). **Память и конкуренция фоновых задач:** страницы и API не читают KSC и не грузят в память целые источники; тяжёлое — только в worker, порциями, под `services/resources.py` (`RES.heavy`, `RES.breathe`); новые тяжёлые операции без порционной обработки и ограничителя не добавляются. Замеры — `python -m app.tools.perf`, `tests/perf/`. SQLite в тестах не проверяет длину строк — длины столбцов сверяет `test_enum_values_fit_postgres_column_lengths`.
- **Фоновые задания — только под арендой** (`app/services/jobs.py`: `JOBS.acquire/run`, `lease.fence(db)` в транзакции записи результата): «выполняется» = есть действующая аренда, а не строка статуса в таблице результатов; зависимые задачи опираются на последний готовый результат (`built_at`), а не на статус `building`. Новое фоновое задание: аренда на (вид, источник), независимая задача на источник, запись результата одной транзакцией с `fence`, уникальность ключей до записи. Подробно: [docs/JOBS.md](docs/JOBS.md).
- **План устранения и категории уязвимостей:** `backend/app/vdb/classify.py` (категории по роли продукта: решение администратора → endoflife.date → название → платформа), `vdb/classmap.py`, таблицы `vdb_finding_products` (находка × продукт, строится в `vdb/sync.analyze`) и `product_classes`; единицы подсчёта не смешивать (уникальные уязвимости / продукты / компьютеры — [docs/VULNDB.md](docs/VULNDB.md)); `GET /vdb/plan`, `/vdb/classes`.
- **XLSX — только потоком:** `reports/xlsx.py` (`Book`/`Sheet`, openpyxl `write_only`): обычная книга держит объект на ячейку (100 тыс. строк = ~1 ГБ). Ширины, закрепление и печать — до первой строки листа. **Замена результатов фоновых расчётов** — одной транзакцией под `db.xact_lock(...)` (иначе два процесса дают `UniqueViolation`); уникальность ключей проверять до записи (`eol/compute.check_unique`). **Кэш страниц к KSC** — `services/cache.TtlCache.get(..., swr=)`: `make` не должен зависеть от запроса (сессия БД).
- **Оборудование и ресурсы Linux-серверов:** `backend/app/ksc/hardware.py` (сводка, `evaluate`, `attach` — только Linux; нет данных — без оценки), запросы `HW_*`, настройки группы `hardware`, проблемы `hw_cpu`/`hw_ram` в `ksc/protection.py PROBLEMS`, столбцы `p_hwc/p_hwr/hw_crit` в зонах, `GET /hosts/{id}/hardware`, `components/HostHardware.tsx`. Подробно: [docs/HARDWARE.md](docs/HARDWARE.md).
- **EOL, устройства, пользователи, «Все источники»:** `backend/app/eol/` (правила и сопоставление), `backend/app/devices/` (опрос `hst_user_visited`, таблица устройств), `app/netsearch.py` (единый поиск: имя, IP, CIDR, логин), `api/{eol,devices}.py`, страницы `EolPage`, `DevicesPage`, компонент `CompactList` (в ячейках таблиц — не больше трёх значений и «+N», экспорт полный). Подробно: [docs/EOL.md](docs/EOL.md), [docs/DEVICES.md](docs/DEVICES.md). KSC не хранит даты входа и «последнего пользователя» — не выдумывать их; новые endpoints, работающие со всеми источниками, берут `source_scope`, права на источники не обходятся.
- **BI-выгрузки и владельцы устройств:** `backend/app/bi/` (`profile.py` — поля и нормализация строки, `xlsx.py` — безопасное потоковое чтение, `smb.py` — SMB только чтение и выбор файла, `importer.py` — проверки и публикация одной транзакцией, `match.py` — сопоставление с KSC, `read.py` — карточки, списки, `owners_for`/`attach_owners` для списков KSC, `service.py` — worker), `api/bi.py`, отчёт `reports/quick_bi.py`, `components/OwnerBlock.tsx`, `pages/people/`, `pages/admin/BiSourcesAdmin.tsx`. История не удаляется (прежний владелец — `present=False`); даты связей — даты выгрузок; одинаковое имя — не доказательство идентичности (только «предполагаемое» при подтверждающем признаке, «надёжное» — решение администратора); IP не используется; данные BI не меняют показатели защиты KSC. Подробно: [docs/BI.md](docs/BI.md).
- **Продукт в каталоге:** встроенное описание `P(...)` в `ksc/catalog.py BUILTIN` (шаблон имени, схема версий, правило ветки) с тестом в `tests/test_versions.py`; ошибки группировки на конкретной установке исправляются в интерфейсе (Администрирование → Каталог программ).

## Проверка перед изменениями

```bash
cd backend && .venv/bin/python -m pytest -q            # модульные тесты (SQLite, подставной KSC)
tests/ksc_synthetic/run.sh up && KSC_TEST_HOST=127.0.0.1 backend/.venv/bin/python -m pytest -q backend/tests/test_ksc_live.py   # SQL-шаблоны на SQL Server
cd frontend && npm run build
python3 scripts/check_private_data.py
```

Не выполняйте массовые проверки и нагрузочные тесты на производственных SQL Server.
