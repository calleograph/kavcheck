# Устройства и пользователи

Раздел «Устройства и пользователи» — единая таблица: имя, IP, ОС, источник KSC, группа администрирования, зоны ответственности, последнее подключение к KSC, пользователи и число проблем поддержки (EOL). Данные берутся из подготовленных данных зон ([ZONE_CACHE.md](ZONE_CACHE.md)), накопленных наблюдений за пользователями и результатов EOL ([EOL.md](EOL.md)); KSC страница не опрашивает.

## Что есть в KSC 15.1 о пользователях (и чего нет)

Проверено по словарю базы настоящего KSC 15.1 и выборке данных:

| Объект | Что хранит | Чего нет |
|---|---|---|
| `hst_user_visited` (`nHost`, `nUser`, `bActual`, `binId`, `binSidHash`) | для устройства — пользователи **в текущем списке вошедших** (`bActual = 1`) и **входившие ранее** (`bActual = 0`) | **ни даты, ни времени входа или выхода** |
| `v_akpub_hst_loggedin_users` | то же только для `bActual <> 0` | — |
| `ak_users` (`wstrSamAccountName`, `wstrUserPrincipalName`, `wstrDisplayName`, `nHostId`, `nDomain`) | учётные записи (доменные и локальные устройств) | — |

Следствия: в KSC **нет «последнего пользователя»** и нет истории входов. В выборке настоящей базы в текущем списке был лишь около 7 % записей (остальные — «входили ранее»), у ~28 % записей `nUser` пуст (учётная запись не сопоставлена, есть только хэш SID). Поэтому KAV Checker не показывает дат, которых нет, и честно различает:

* **Вошли сейчас** — пользователи в списке вошедших при последнем опросе.
* **Последний замеченный в сеансе** — пользователь, которого последний опрос застал в списке вошедших; показывается **дата наблюдения**, а не время входа.
* **За 7 суток** — замеченные в списке вошедших за 7 суток либо впервые появившиеся в списках после начала наблюдений (значит, входили между опросами). Записи, существовавшие при первом опросе источника, **без даты**: в «7 суток» они не входят, пока не будут замечены в сеансе.
* **Входили ранее** — список «ранее» из KSC, без дат.

Ограничения: короткие сеансы между опросами не видны (интервал настраивается, по умолчанию 60 минут); история начинается с первого опроса источника; запись без сопоставленной учётной записи показывается как «учётная запись не сопоставлена в KSC», логин не выдумывается.

## Служебные учётные записи

Не считаются пользователями и по умолчанию скрыты: системные (SYSTEM, LOCAL SERVICE, NETWORK SERVICE, DWM-N, UMFD-N, Font Driver Host, Window Manager, «имя$», root, daemon, gdm и т. п.) и служебные по маскам настройки (`svc*`, `*_svc`, `krbtgt` …; «Администрирование → EOL и пользователи»). Переключатель «Показывать служебные и системные учётные записи» возвращает их в таблицу.

## Опрос

Фоновая служба (`devices/service.py`) раз в `interval_minutes` читает `hst_user_visited` с `ak_users` порциями по `nId` (по 20 000 строк; только `SELECT`, шаблон `USERS_VISITED` проходит защиту `ksc/guard.py`) и обновляет таблицу `dev_users`; состояние — `dev_state`. Источник без нужных объектов (`FEATURE_OBJECTS["users"]`) пропускается, ошибка источника не мешает остальным и повторяется через 10 минут, накопленное сохраняется. Наблюдения за пользователями, которых KSC больше не показывает, хранятся `retention_days` (по умолчанию 90).

## Единый поиск

Одно поле для имени, FQDN, IP-адреса и логина. Несколько значений — через пробел, запятую или точку с запятой (подходит любое).

| Значение | Пример |
|---|---|
| Имя, FQDN, логин с масками `*` | `srv-*`, `*-db`, `*sql*`, `ivanov`, `petr*` |
| IP-адрес | `192.0.2.15` |
| Сеть CIDR | `192.0.2.0/24` |
| Диапазон | `10.1.2.5-10.1.2.40`, `10.1.2.5-40` |
| Маска по октетам | `10.1.*`, `192.0.2.*` |

Адрес в KSC — число (`nIp`, первый октет в старшем байте), поэтому адреса ищутся **по диапазону чисел**, а не по тексту: быстро на сотнях тысяч устройств (индекс `ix_zc_hosts_ip`; в KSC — по `h.nIp BETWEEN`). Значения передаются только параметрами SQL. Поиск работает в разделах «Устройства и пользователи» (имя, IP, логин) и «Компьютеры» (имя, IP, логин, если источник отдаёт таблицы пользователей). Некорректный адрес или сеть — понятная ошибка 422.

## «Все источники»

Список источников в верхней панели начинается с пункта «Все источники»: он включает все доступные пользователю источники (включая добавленные позже), не обходит права и работает в разделах «EOL», «Устройства и пользователи», «Отчёты». В остальных разделах показывается выбранный источник — об этом говорит заметка вверху страницы. У каждой записи указан источник (там, где источников больше одного). Недоступный источник (ошибка проверки) помечается предупреждением: показаны сохранённые данные. Технически — заголовок `X-Source-Id: all` (`auth/deps.py: source_scope`).
