# Архитектура

## Компоненты

```
Браузер ──HTTPS──► внешний reverse proxy (TLS) ──► web (nginx + React SPA)
                                                      │ /api/ → backend (FastAPI)
                                                      │              ├── postgres (внутренняя база)
                                                      │              └── SQL Server баз KSC (только чтение, pymssql)
                                                   worker (тот же образ backend, python -m app.worker) ──► report_jobs → DATA_ROOT/reports
                                                   помощник обновлений на хосте (scripts/updater.sh) ◄── DATA_ROOT/updater
```

| Сервис | Технология | Ответственность |
|---|---|---|
| `web` | nginx unprivileged + собранный React/TypeScript | статика, прокси `/api/` к backend, заголовки безопасности и CSP |
| `backend` | Python 3.12, FastAPI, SQLAlchemy async, Alembic | вход, сессии, роли, источники KSC, реестр ПО, компьютеры, уязвимости, отчёты (постановка и выдача), настройки, журналы |
| `worker` | тот же образ | фоновое формирование отчётов: опрос таблицы `report_jobs`, построение, XLSX/CSV, отмена, очистка по сроку |
| `postgres` | PostgreSQL 16 | внутренняя база: пользователи, сессии, настройки, источники, правила, сценарии, отчёты, журналы, кэш |

Контейнеры работают не от root, с `no-new-privileges`, перезапускаются после перезагрузки сервера (`restart: unless-stopped`), имеют healthcheck. Наружу публикуется только порт web (по умолчанию loopback).

## Данные

- Внутренняя база — только через Alembic (`backend/migrations`). Модели — `backend/app/models.py`.
- `DATA_ROOT`: `postgres/`, `reports/<job_id>/{rows.jsonl,report.xlsx,report.csv}`, `backups/`, `updater/` (канал с помощником), `state/`.
- Базы KSC не изменяются никогда.

## Безопасность

- Сессии серверные (таблица `sessions`, в cookie только случайный идентификатор, HttpOnly, Secure, SameSite=Lax); CSRF-токен в заголовке `X-CSRF-Token`, проверка Origin по `APP_PUBLIC_URL`/`ALLOWED_ORIGINS`.
- Защита от перебора паролей: блокировка логина после N неудач.
- Роли проверяются зависимостями FastAPI (`require_user`, `require_analyst`, `require_admin`); доступ к источнику — `current_source` на каждом запросе.
- Пароли источников и LDAP зашифрованы AES-256-GCM (`APP_MASTER_KEY` из окружения), не возвращаются API, маскируются в журналах.
- SQL к KSC: только шаблоны с параметрами, `guard.check` до подключения, `READ UNCOMMITTED` и `LOCK_TIMEOUT` на соединении, тайм-ауты, предел строк, семафор одновременных запросов на источник, учётная запись только для чтения (диагностика предупреждает о правах на запись).
- Обновления из браузера — через помощника с белым списком действий; значения запроса проверяются по шаблонам, устаревшие и чужие запросы отбрасываются.

## Слои backend

```
api/*.py          маршруты (тонкие), схемы pydantic (api/schemas.py)
auth/             сессии, зависимости и роли, LDAP, сценарий входа
services/         настройки (группы), аудит и журнал, реестр клиентов источников, канал обновлений, локальные учётные записи
ksc/              адаптер KSC: driver (pymssql), guard, queries (шаблоны), schema (диагностика/совместимость), versions, grouping, software, hosts, dashboard, vulns
reports/          builder (виды отчётов), export (JSONL/CSV/XLSX), runner (воркер)
```

## Совместимость с версиями KSC

Шаблоны опираются на публичные представления `v_akpub_*` и внутренние таблицы реестра ПО и уязвимостей, проверенные на KSC 15.1. При добавлении источника проверяется наличие объектов для каждой функции (`ksc/queries.py: FEATURE_OBJECTS`); отсутствующие функции помечаются как недоступные для источника, остальные работают. Сводная отчётность по нескольким источникам возможна в будущем: каждый отчёт уже хранит источник и время получения данных.

## Будущие модули

Состояние защиты, события безопасности, аудит лицензий, сравнение периодов, сводные отчёты по нескольким KSC. Они используют те же компоненты: источники, роли, фильтр активности, построитель отчётов и экспорт, журналирование. Страницы-заглушки уже есть в навигации.
