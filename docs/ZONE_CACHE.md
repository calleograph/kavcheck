# Подготовленные данные зон: ночной расчёт и кэш дашбордов

Страницы зон ответственности, фильтр «Зона» в разделах и отчёты по зонам **не обращаются к KSC и не запускают расчёт при открытии**. Всё тяжёлое выполняет фоновая служба (worker) заранее — ночью по расписанию или по явному запросу, а результат хранится в PostgreSQL и переживает перезапуск контейнеров и сервера.

## Что считается и где хранится

| Таблица | Содержимое |
|---|---|
| `zc_sources` | по источнику KSC: текущее поколение данных (`gen`), время и срез (`built_at`), длительность, ошибка последнего расчёта, отпечаток данных KSC (`stamp`) и результат лёгкой проверки (`probe_stamp`) |
| `zc_hosts` | компьютер: колонки для фильтров и итогов (активность, в сети, возраст баз и проверки, признаки проблем защиты, счётчики обнаружений KSC и внешних баз по уровням, принятые и исключённые, спорность), `data` — остальные сведения для карточки и отчётов |
| `zc_hostzones` | принадлежность компьютера зоне (`none` — без ответственного); пересчитывается при изменении зон без обращения к KSC |
| `zc_detections` | обнаружения (подтверждённые KSC и потенциальные по внешним базам) с решением специалиста: корзина `current` / `accepted` / `excluded`, эффективное решение, строка для карточки и отчётов |
| `zc_dashboards` | готовая сводка зоны (показатели, данные диаграмм, спорные, срез данных, отпечатки источников) |
| `zc_jobs` | задания расчёта: ночной пересчёт всех зон (`all`), обновление одной зоны (`zone`), пересчёт состава зон (`members`) |

Что читает интерфейс:

* **Открытие зоны** — одна строка `zc_dashboards` (показатели и диаграммы) и страница таблицы компьютеров (`LIMIT` ≤ 500, фильтры и сортировка — SQL по индексам). При нестандартных порогах («старые базы N суток», «проверка N суток», без внешних баз) показатели считаются теми же агрегатами SQL «на лету»: это миллисекунды, KSC не затрагивается.
* **Карточка компьютера** — строки одного компьютера из `zc_detections`.
* **Фильтр «Зона»** в «Компьютерах», «Уязвимостях», «Защите», «Программах» — идентификаторы компьютеров из `zc_hostzones`.
* **Отчёты и рассылки** — наборы из сохранённых данных порциями по компьютерам зоны; в отчёте указан **срез данных KSC** (время, когда данные получены из KSC).

Объём и состав:

* для потенциальных совпадений с внешними базами в списке хранятся самые опасные `ext_per_host` (60) на компьютер — сначала из каталога CISA KEV, затем по уровню и достоверности; **показатели учитывают все совпадения**, строки с решениями специалистов сохраняются всегда. Итоги считаются по версиям каталога, а не перебором совпадений компьютера;
* строки обнаружений хранятся компактно (длинные пояснения и повторяющиеся поля восстанавливаются при чтении);
* поиск по CVE/KLA и программе в таблице зоны идёт по спискам идентификаторов компьютера (`zc_hosts.kk/ke/pk/pe`, триграммные индексы PostgreSQL `pg_trgm`, если расширение доступно); сочетание «CVE и программа в одной строке» и фильтр по состоянию обработки читают строки обнаружений;
* таблицы `zc_*` **не входят в резервную копию** (`backup.sh --exclude-table-data='zc_*'`): это производные данные, после восстановления базы расчёт запускается сам.

## Как идёт расчёт (потоково)

Чтение KSC — порциями, в памяти всегда одна порция и компактные счётчики:

1. компьютеры — порциями по 200 / 400 / 800 (интенсивность): запись, защитные продукты, зоны;
2. обнаружения KSC — потоком по `o.nId` (по 20 000 строк): решения специалистов применяются при записи строки;
3. потенциальные совпадения с внешними базами — по порциям компьютеров из компактного индекса «запись реестра → версия каталога → уязвимости» (индекс строится порциями по уязвимостям);
4. итоги по компьютерам, затем **подмена поколения одной транзакцией**; сводки зон заменяются после этого.

Ошибка, остановка, перезапуск worker или нехватка памяти — новое поколение удаляется, видимые данные не менялись; задание возвращается в очередь и безопасно повторяется с начала. Если расчёт не удался, показываются прежние данные с отметкой возраста и причиной ошибки.

## Задания и защита от лишней нагрузки

* Активное задание каждого вида одно (`dedupe_key` + частичный уникальный индекс): повторное нажатие «Обновить данные» не создаёт копий.
* Тяжёлые фоновые задачи worker — расчёт зон, анализ уязвимостей, сборка каталога — идут под общим ограничителем (`services/resources.py`): по умолчанию по одной; остальные ждут в очереди. Отчёты пользователей получают отдельное место сверх фоновых, чтобы ночной расчёт не задерживал их на десятки минут (память при этом по-прежнему проверяется). Число одновременных фоновых задач и интенсивность задаются в «Администрирование → Расчёт данных зон».
* Память worker ограничена с двух сторон: контейнер (`WORKER_MEM_LIMIT`, по умолчанию 3 ГБ, без swap) и собственные пределы процесса — мягкий (50 %: новая тяжёлая задача откладывается) и жёсткий (75 %: текущая задача останавливается на границе порции, освобождает память и повторяется позже). Пределы — страховка; потребление держится низким за счёт порционной обработки.
* После перезапуска worker задание `running` без пульса 10 минут возвращается в очередь; после пяти попыток подряд — ошибка.

## Расписание и настройки

«Администрирование → Расчёт данных зон»: включение ночного расчёта, время и часовой пояс (по умолчанию — организации), число тяжёлых задач, интенсивность, предел обнаружений на источник (больше — сохраняются только счётчики по компьютерам), порог возраста данных для отчётов по расписанию. Раздел показывает следующий плановый запуск, время и длительность последнего успешного расчёта, состояние источников, очередь заданий и память worker. Если worker был выключен в плановое время, расчёт выполняется при запуске (в пределах 6 часов), иначе — в следующую ночь.

Первый расчёт нового источника (и после обновления до версии с подготовленными данными) запускается автоматически, не дожидаясь ночи.

## Актуальность

* Рядом с дашбордом — «Данные обновлены: дата, время».
* Раз в 15 минут worker выполняет лёгкую проверку KSC (число компьютеров и действующих обнаружений, наибольшие идентификаторы). Если отпечаток изменился или обновились базы уязвимостей и каталог, страница показывает ненавязчивое уведомление о более свежих сведениях; пересчёт автоматически **не** запускается.
* Кнопка «Обновить данные» (аналитик, администратор) ставит в очередь пересчёт только этой зоны (компьютеры зоны читаются из KSC заново); запрос возвращается сразу, ход виден на странице, старый дашборд остаётся доступным.
* Изменение зон (правила, закрепления, CSV) и решения по уязвимостям применяются к сохранённым данным без обращения к KSC: состав зон — заданием `members`, решения — сразу.
* Отчёт по зоне (в том числе по расписанию) использует подготовленные данные и указывает срез. Параметр «Обновить данные зоны из KSC перед формированием» выполняет обновление перед отчётом; рассылка по расписанию делает это сама, если данным больше `stale_hours` (по умолчанию 36 ч).
