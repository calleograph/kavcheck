# Журналы и хранение

Журналы не объединяются в один файл: у каждого типа свой владелец, место и срок. Общий — только интерфейс (Администрирование → «Журналы и хранение») и правила ротации (`backend/app/services/retention.py`).

| Журнал | Владелец | Где хранится | Формат | Назначение | По умолчанию |
|---|---|---|---|---|---|
| Журнал событий приложения | backend, worker | PostgreSQL, `event_log` | строки таблицы | ошибки и предупреждения служб, входы, источники KSC, каталог программ, EOL, базы уязвимостей, отчёты, система | 30 суток, 500 МБ, без архива |
| Журнал действий (аудит) | backend | PostgreSQL, `audit_log` | строки таблицы | кто, что и когда сделал; обязательные события | не удалять; при заданном сроке (от 90 суток) — только после переноса в архив |
| Журналы выполнения заданий Pentest | сканер | PostgreSQL, `pt_events` | нормализованные события | ход и диагностика заданий (Nmap, NSE, Nuclei, сопоставление) | 90 суток, 200 МБ, без архива |
| Результаты сканирований | сканер | PostgreSQL, `pt_*` | — | находки, порты, хосты | срок задаёт Pentest («Хранение заданий»); настройками журналов не затрагиваются |
| Журналы контейнеров | Docker | json-file | JSON-строки | вывод backend, worker, сканера, web | ротация в `deployment/compose.yml` (max-size, max-file) |

Операционные журналы, аудит и результаты сканирований имеют разные требования к хранению и настраиваются раздельно. Событие не дублируется во всех хранилищах: Docker получает вывод процесса, база — события, которые нужно искать и показывать в интерфейсе.

## Что делает ротация

Раз в `rotate_hours` (24) worker выполняет по порядку: срок хранения → предел объёма → срок и число архивов → общая квота → проверка свободного места.

* **Срок**: записи старше срока удаляются порциями (по 2000, без загрузки таблицы в память). Для журнала событий можно задать срок по категориям (`auth`, `ksc`, `report`, `catalog`, `worker`, `admin`, `system`).
* **Архив**: если включён (для аудита — всегда), записи сначала пишутся в сжатый файл `journal|audit|pt_events-ГГГГММДД-ЧЧММСС-NN.ndjson.gz` (каталог `reports/_logs/archive`), после подтверждения записи порции удаляются. Ротация по размеру: при `archive_file_mb` начинается следующий файл.
* **Предел объёма**: у операционных журналов старейшие записи удаляются, пока объём не станет ниже 90 % предела. У аудита предел только предупреждает.
* **Архивы**: удаляются по сроку (`archive_days`) и по числу (`archive_max_files`). Архивы аудита удаляются только если срок хранения аудита ограничен.
* **Общая квота** (журналы + архивы): при превышении записи операционных журналов старше половины срока сжимаются в архив (данные сохраняются), затем удаляются старейшие архивы, **срок хранения которых уже истёк**. Если уложиться нельзя без нарушения правил, администратор видит предупреждение — данные молча не теряются.
* **Диск**: предупреждение при свободном месте меньше `disk_warn_free_mb` — до того, как это затронет PostgreSQL.
* Очистка откладывается, пока выполняется сканирование Pentest (кнопка «Очистить сейчас» выполняет её принудительно). Сбой записи журнала не влияет на работу приложения.

Скачать и удалить архив может только администратор; скачивание записывается в журнал действий.

## Журнал сканирования Pentest

Каждое задание хранит нормализованные события (`pt_events`): время, уровень (INFO / WARN / ERROR / DEBUG), движок, этап, адрес и порт, проверка, код завершения, длительность, возможность безопасного повтора, номер запуска (после перезапуска сканера — следующий). Сырой вывод Nmap и Nuclei не сохраняется; секреты скрываются до записи. События пишутся пачками (один коммит на десятки записей), на задание — не более 3000 записей (из них хода — 1200; сбои сохраняются). Скачивание: TXT для чтения и JSONL для обработки (`GET /pentest/jobs/{id}/log/download?fmt=txt|jsonl`). Живой журнал — опрос с курсором (`after`), после обрыва связи продолжается без потерь.
