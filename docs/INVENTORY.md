# Инвентаризация (учёт ИТ-активов)

Раздел «Инвентаризация» (`/inventory`) — второй контур KAV Checker. Технический аудит и безопасность, как и раньше, опираются на KSC. Инвентаризация добавляет **учётную составляющую** имущества:

- инвентарные номера и принадлежность;
- местоположение и движение;
- ответственных лиц;
- документы (акты, перемещения, ремонты, списание);
- лицензии;
- историю на протяжении всего срока службы.

Технические сведения второй раз не собираются. Процессор, память, накопители, сеть, установленное ПО, владелец по BI и состояние защиты берутся из уже имеющихся данных KAV Checker. Для этого учётная карточка связывается с компьютером KSC. Данные KSC только читаются: изменение учётных полей источники не затрагивает.

## Где что находится

| Раздел | Что в нём |
|---|---|
| Обзор | состав и состояние, учётная стоимость, связь с KSC, «Требует внимания» (каждое число открывает список), незавершённые документы, последние изменения |
| Оборудование | реестр с поиском по всем полям и свойствам, фильтрами, сохранёнными фильтрами, группировкой, массовыми операциями, созданием карточек из KSC (несколько источников сразу, только выходившие на связь за N суток), этикетками и отчётом по выборке |
| Карта оборудования | сетевые наблюдения, группировка по странам, регионам, городам и площадкам, фильтры и отчёт. Администратор настраивает правила принадлежности и смотрит предпросмотр |
| Карточка | вкладки: учётные сведения, расположение и ответственные, техника (KSC), ПО и лицензии, состав и связи, документы, история (и состояние на дату), вложения |
| Документы | выдача, возврат, перемещение, приём-передача, передача МЦ, приём неисправного, ремонт, списание, работы; этапы; «Сформировать документ» — файл Word (DOCX), Excel (XLSX), PDF, HTML или печатная форма в приложении |
| Местоположения | дерево «регион → город → адрес → здание → этаж → помещение → рабочее место», площадки, серверные, стойки, склады; число единиц в узле и поддереве; этикетки помещений |
| Сотрудники | сотрудники учёта (вручную, из BI, из адресной книги); закреплённое оборудование по ролям, история закреплений, возврат или снятие ролей при увольнении |
| Лицензии | купленные лицензии: количество, срок, назначения, установки по данным KSC, расхождения; сам ключ активации не хранится — только ссылка на запись в парольном менеджере |
| Отчёты | каталог отчётов с отбором и периодом |
| Сканирование | камера телефона или ручной сканер: QR, штрихкод, инвентарный или серийный номер ведут в карточку |
| Справочники | типы, производители и модели (со значениями свойств по умолчанию), статусы, поставщики и сервисные организации, подразделения, филиалы, типы лицензий, категории программ, дополнительные свойства |
| Импорт | Excel или CSV: сопоставление столбцов, проверка без записи, импорт с отчётом об ошибках |
| Настройки | права по ролям и учётным записям, области учёта, нумерация, печатные формы, этикетки, сроки контроля (только администратор) |

В карточке компьютера («Компьютеры» → компьютер) есть блок «Инвентаризация». В нём показаны инвентарный номер, категория и статус, местоположение, пользователь и владелец, ответственный и МОЛ, дата изменения учётных сведений и ссылка на учётную карточку. Если связи нет, блок предлагает карточки с тем же именем для сопоставления или создание новой карточки.

## Модель данных

| Таблица | Назначение |
|---|---|
| `inv_assets` | Учётная единица. Хранит: `uid` для QR, инвентарный и бухгалтерский номера, серийный номер, тип, модель, статус, местоположение, пять ролей сотрудников, приобретение и гарантию, стоимость в копейках, `props` (дополнительные свойства), связь с KSC (`ksc_source_id` + `ksc_host_id`, состояние `confirmed` / `auto` / `lost`), `parent_id` (состав, ВМ на хосте, подключение), `ext_ids` (идентификаторы других систем), `version` (защита от одновременной правки) |
| `inv_history` | Событие истории: изменения «было → стало», состояние **после** события (по нему строится «состояние на дату»), основание, документ, участвовавшие сотрудники |
| `inv_locations` | Дерево местоположений. `path` — полный путь, `ids_path` — выборка поддерева одним условием |
| `inv_refs` | Справочники. У типа есть класс, у статуса — состояние учёта, модель привязана к производителю и может хранить значения свойств по умолчанию |
| `inv_props` | Определения дополнительных свойств: тип, варианты, значение по умолчанию, обязательность, типы оборудования, показ в списке |
| `inv_people` | Сотрудники учёта; `source` и `ext_key` — откуда перенесён сотрудник (BI, адресная книга) |
| `inv_docs`, `inv_doc_items` | Документы и их строки. Строка хранит сведения единицы на момент оформления (`snap`) |
| `inv_licenses`, `inv_lic_assign` | Лицензии, назначения единицам и сотрудникам, последний подсчёт установок (`usage`) |
| `inv_files` | Вложения до 15 МБ. Хранятся в базе, поэтому попадают в резервные копии |
| `inv_views` | Сохранённые фильтры, личные или общие |

Миграции — `0035_inventory`, `0036_inv_counts`, `0037_infra`. Расширение карточки делается дополнительными свойствами и справочниками, без новых столбцов. Чтобы добавить тип оборудования, менять схему не нужно.

**Классы** (фиксированы, на них опираются правила): рабочая станция, ноутбук, физический сервер, виртуальный сервер, монитор, принтер и МФУ, сетевое оборудование, СХД, периферия, комплектующее, прочее. **Состояния учёта** (тоже фиксированы): на складе, в эксплуатации, зарезервировано, в ремонте, списано, выведено из эксплуатации, утрачено. Типы и статусы — справочники администратора, у каждого указан класс или состояние.

## Правила

- **История — у каждого изменения.** Создание, правка, массовая операция, документ, импорт, связь с KSC, вложения и лицензии записываются событием карточки. В событии есть кто и когда, «было → стало», основание и ссылка на документ. В журнал действий (`inv.*`) пишется сама операция. Карточки не удаляются: списание и вывод из эксплуатации — это статусы.
- **Состояние на дату** берётся из последнего события не позже этой даты. Каждое событие хранит учётное состояние после себя: статус, местоположение, пять ролей, подразделение.
- **Одновременная правка.** Если карточку уже изменил другой пользователь, сохранение отклоняется со ссылкой на автора. Перед повтором нужно обновить страницу.
- **Документы меняют карточки на «своём» этапе:**
  - перемещение: «Отправлен» ставит отметку «в пути», «Принят» записывает новое местоположение и ответственных;
  - ремонт: «Отправлен» ставит статус «В ремонте» и запоминает прежний, «Завершён» возвращает прежний;
  - остальные документы меняют карточки при проведении.
  Единица «в пути» не попадает в другое перемещение, выдачу или возврат. Списанное нельзя выдать.
- **Связь с KSC.**
  - Устойчивый ключ связи — «источник + идентификатор компьютера KSC». Создание карточек из KSC и повторный импорт не порождают дублей: эта пара уникальна.
  - Имя компьютера только **предлагает** связь, когда оно совпало ровно с одним компьютером всех источников. Такая связь получает состояние «предполагается», и её подтверждает пользователь.
  - Если компьютер исчез из KSC, связь отмечается «нет в KSC», а карточка сохраняется. Сверку раз в 15 минут выполняет worker по подготовленным данным, сам KSC при этом не опрашивается.
  - Расхождения серийного номера и имени между карточкой и KSC показываются, но автоматически не исправляются.
- **Область учёта.** Учётной записи можно ограничить видимость поддеревьями местоположений: «Настройки → Права доступа». Такой пользователь видит и меняет только оборудование в разрешённых местах. Отчёты строятся по его области: сервер подставляет её сам, параметр клиента игнорируется.
- **Ключи лицензий** шифруются ключом `APP_MASTER_KEY`. В списки, карточки и отчёты ключи не попадают. Ключ выдаётся отдельным запросом с правом «просмотр ключей лицензий», и каждое открытие пишется в журнал действий.

## Права

Право даётся по наименьшей роли (настраивается). Сверх роли учётной записи можно выдать отдельные права.

| Право | По умолчанию |
|---|---|
| просмотр оборудования | просмотр |
| создание карточек; изменение учётных свойств; изменение местоположения; изменение владельцев и ответственных; оформление документов; оформление ремонтов; инвентаризация; импорт | аналитик |
| просмотр ключей лицензий | специалист по ИБ |
| списание; справочники и местоположения; печатные формы и этикетки | администратор |

Выгрузка отчётов, как и во всём KAV Checker, доступна начиная с аналитика. Ответственному за зону раздел недоступен.

## Отчёты

Вид отчёта — `quick_inv`. Отчёт строится по тем же параметрам отбора, что и список. Если строки выбраны флажками, отчёт строится по ним. Форматы — XLSX, CSV, PDF, HTML. В HTML логические части разложены по вкладкам, в XLSX — по отдельным листам.

| Вид | Содержание |
|---|---|
| `registry`, `computers` | реестр ИТ-оборудования; реестр компьютеров и серверов (имя, ответственные, связь с KSC) |
| `card` | карточка единицы: учётные сведения, свойства, состав, документы, история, лицензии |
| `by_person`, `by_resp` | оборудование по сотрудникам (любая роль) и по ответственным |
| `by_location` | состав по местоположениям |
| `stock`, `repair`, `warranty`, `writtenoff`, `cost` | склад и резерв; ремонт с открытыми ремонтами; истекающая гарантия; списанное; стоимость по типам, местоположениям, подразделениям |
| `owner_history`, `moves` | история принадлежности и история перемещений за период |
| `hardware`, `software` | аппаратная конфигурация и установленное ПО связанных компьютеров (из KSC, группами) |
| `licenses`, `license_usage` | реестр лицензий; куплено, назначено, установлено, расхождения |
| `components`, `docs`, `duplicates` | состав и комплектующие; журнал документов; возможные дубли (совпадение серийного номера или имени) |

**Печатные формы документов** — акт выдачи, акт возврата, акт внутреннего перемещения, акт приёма-передачи, акт передачи материальных ценностей, акт приёма неисправного оборудования, направление в ремонт, акт списания, наряд на работы.

- В форме только сведения документа: номер и дата, стороны, основание, таблица оборудования, места для подписей. Технических полей KSC в актах нет.
- Шапка формы берётся из «Организация и отчёты».
- Настраиваются заголовок, вводный текст с подстановками, столбцы, дополнительные свойства в таблице, подписи и заключительный текст.
- Форма открывается в приложении (лист A4, печать из браузера) и скачивается как PDF, DOCX (для правки) и HTML.

**Этикетки:**

- PDF: страница на этикетку для принтера этикеток или лист A4 с сеткой для клеящейся бумаги;
- ZPL для принтеров Zebra;
- код — QR со ссылкой на карточку (камера телефона открывает её сразу), штрихкод Code 128 с инвентарным номером, или оба;
- этикетка помещения несёт код `LOC:<id>` для будущей инвентаризации со сканированием.

## Импорт Excel / CSV

- Первая строка файла — заголовки. Столбцы сопоставляются с полями по названиям, сопоставление можно поправить вручную.
- Совпадение с существующей карточкой ищется по инвентарному номеру, затем по однозначному серийному номеру.
- Режимы:
  - «только новые»;
  - «новые и обновление» — меняются только сопоставленные столбцы, пустая ячейка значение не стирает.
- Отсутствующие значения справочников, местоположения (по пути «А / Б / В») и сотрудники (по почте или ФИО) создаются, если это разрешено. Классы типов и состояния статусов автоматически не создаются.
- «Проверить» показывает, сколько карточек будет создано и изменено, и ошибки по строкам; в базу ничего не записывается. Импорт выполняется построчно: строка с ошибкой пропускается и попадает в отчёт.
- Повторная загрузка того же файла дублей не создаёт.
- Шаблон файла (Excel или CSV, пустой или с вымышленным примером) скачивается на странице импорта: столбцы — поля карточки и действующие доп. свойства, в Excel на втором листе описано, что указывать. CSV — разделитель «;», UTF-8.
- Ограничения: до 20 000 строк и 30 МБ на файл.

## Пакетное редактирование

В «Оборудовании» отметьте отдельные карточки, текущую страницу или всю отфильтрованную выборку. При выборе всей выборки можно снять отметки с отдельных строк. Сервер применяет те же фильтры, что и реестр, в пределах области учёта пользователя. При изменении отбора выделение сбрасывается.

Кнопка «Изменить» открывает выбор полей и значений. Доступны тип и модель, статус, подразделение, филиал, зона, персональные роли, узел местоположения, назначение, теги, реквизиты и дополнительные свойства по действующим правам пользователя. Страна, регион, город, здание, этаж и помещение задаются через узел дерева местоположений. Инвентарные номера, серийные номера, имя узла KSC и связи с источниками обслуживаются в карточке и импорте.

Предпросмотр показывает количество выбранных и изменяемых устройств, поля и ошибки отдельных карточек. Режим «Заполнить пустые» пропускает заполненные свойства, режим замены применяет только выбранные поля. Применение сверяет версии карточек с предпросмотром. Если подбор изменился, откройте предпросмотр заново. Успешные изменения записываются в историю каждой карточки и журнал действий одной транзакцией.

## Сетевое местоположение и карта

В карточке на вкладке «Расположение и ответственные» отдельно показаны учётное местоположение, подразделение и зона, ответственные и последнее сетевое наблюдение. Снимок связан с карточкой по устойчивой паре «источник KSC + компьютер». Worker читает KSC порциями, обычно раз в шесть часов. Ошибка источника сохраняет предыдущий снимок. Дата наблюдения берётся из KSC, дата обработки — из KAV Checker. Через семь суток наблюдение считается устаревшим. Если время неизвестно, это отдельный статус фильтра. [Поля KSC](ksc/DEVICES.md)

Администратор открывает «Карта оборудования → Правила принадлежности». Все указанные условия должны выполниться. Варианты IP и сетей внутри одного поля работают как альтернативы и поддерживают IPv4, IPv6, CIDR и диапазоны. Правило может учитывать источник, адрес устройства или подключения, группу KSC, маску имени, сообщённый домен, тип оборудования и площадку подтверждённого или автоматически сопоставленного объекта инфраструктуры. Сетевое имя и идентификатор участвуют только при наличии данных. Меньшее число приоритета выигрывает. При равном приоритете выигрывает более узкий диапазон. Несовместимые результаты с одинаковым рангом требуют проверки. Подходящее правило VPN или прокси блокирует размещение на карте и учётные предложения для наблюдения.

Для привязки к корпоративной площадке выберите узел дерева «Местоположения» и укажите координаты в нём. Используйте отдельные правила для сетей с одинаковыми диапазонами в разных источниках. Предпросмотр показывает совпадения по последним снимкам, конфликтующие и устаревшие результаты и число устройств, которым можно предложить заполнение. Применение предложения в карточке заполняет пустые поля с учётом прав. Для изменения существующих значений доступно ручное или пакетное редактирование. Смена IP, правила или сетевого наблюдения сама по себе учётную карточку не меняет.

Карта открывается без внешнего сервиса подложки и показывает локальный слой суши Natural Earth. Маркер и список групп открывают выборку. Доступны фильтры по подразделению, учётной зоне, типу, источнику, сети и актуальности. Отчёт использует тот же отбор и права на источники. Корпоративные площадки получают координаты справочника. Публичный IP подключения даёт страну, регион, город, координаты и радиус погрешности, если их возвращает локальная база. ASN и организация берутся из отдельной ASN-базы. [Формат и точность GeoLite2](https://dev.maxmind.com/geoip/geolite2-free-geolocation-data/) · [Условия Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/)

### Географические базы

На чистой установке worker сразу загружает бесплатные базы [DB-IP Lite City и ASN](https://db-ip.com/db/lite.php) без учётной записи, ключа и подписки. После первой загрузки поиск IP полностью локальный. Устройства и их IP-адреса провайдеру не передаются. Для загрузки требуется HTTPS-доступ worker к `download.db-ip.com`.

DB-IP Lite проверяется в первый день месяца по UTC. Если выпуск задерживается, worker проверяет наличие пары за предыдущий месяц и повторяет попытку через шесть часов. Базы проверяются и заменяются парой. При сбое остаётся последняя рабочая пара. Файлы хранятся в томе `geoip_data`, базы DB-IP в его подкаталоге `dbip`. Смена пары ставит в очередь обновление сетевых наблюдений. Данные DB-IP Lite предоставляются по [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Страницы и отчёты с этими данными содержат указание источника и ссылку на [DB-IP](https://db-ip.com/).

В «Инвентаризация → Настройки → Географические базы» можно запустить разовую проверку, отключить обновление или выбрать GeoLite2. Для автоматического GeoLite2 нужны номер учётной записи и ключ MaxMind. Ключ шифруется через `APP_MASTER_KEY`. Ранее заданные реквизиты и расписание GeoLite2 сохраняются при обновлении приложения. Для GeoLite2 чтение версии выполняется раз в сутки через `download.maxmind.com` и официальное хранилище MaxMind. В настройках видны провайдер, этап, даты сборок обеих баз и ошибки. [Обновление GeoLite2](https://dev.maxmind.com/geoip/updating-databases/)

Для ручного GeoLite2 положите `GeoLite2-City.mmdb` и `GeoLite2-ASN.mmdb` в `${DATA_ROOT}/geoip`. Каталог монтируется на чтение. При выбранном GeoLite2 и выключенном автообновлении ручные базы имеют приоритет. Пока выбранный провайдер не загрузил рабочую пару, приложение использует сохранённую пару другого провайдера либо ручные файлы. При отсутствии баз действуют правила корпоративных площадок. [Условия GeoLite2](https://dev.maxmind.com/geoip/geolite2-free-geolocation-data/)

География публичного IP описывает выход в сеть и имеет низкую достоверность для физического местоположения компьютера. NAT, CGNAT, VPN, прокси и мобильная сеть могут скрывать исходное расположение. Тип виртуального или VPN-адаптера сам по себе показывает наличие интерфейса. Улицу и здание берут только из корпоративного справочника, который указан в правиле. Известные ограничения получения IPv6, NLA и иных атрибутов перечислены в карте данных KSC. [Поля KSC](ksc/DEVICES.md)

В карточке есть отдельная строка адреса подключения с типом, исходным полем KSC и временем наблюдения. Уникальный публичный адрес подходит для приблизительной оценки сетевого выхода. Для локального, CGNAT, служебного, отсутствующего или неоднозначного адреса GeoLite2 не используется. Известный шлюз или VPN можно отметить правилом. Данные из офисной, домашней, VPN- и мобильной сети предстоит сопоставить с фактическим маршрутом на рабочем стенде. [Сценарии подключения](ksc/DEVICES.md#адрес-подключения-дома-в-офисе-и-через-посредников)

Отчёт из карточки выгружает оценку и исходные сетевые наблюдения по выбранной единице учёта. Администратор может выгрузить сохранённые правила принадлежности и полный результат предпросмотра черновика. Отчёт с карты использует её текущие фильтры.

## Инвентаризация со сканированием

«Инвентаризация → Инвентаризации». Документ инвентаризации фиксирует **ожидаемый список**: действующее оборудование выбранной области (узел местоположений с вложенными, при необходимости — классы), кроме отмеченного «не подлежит инвентаризации».

- **Сканирование**: камера телефона (QR, Code 128 и другие коды — средствами браузера), ручной сканер или ввод номера. Код распознаётся как ссылка на карточку, инвентарный или серийный номер. **Этикетка помещения** (`LOC:<id>`, печатается в «Местоположениях») переключает текущее помещение. Можно отметить фактического пользователя.
- **Результат отметки**: найдено на месте; найдено в другом месте; не ожидалось (единица из другой области); код не найден в учёте; повтор. На вкладке «По помещениям» — сколько ожидалось, найдено, осталось (готовые помещения выделяются).
- **Автономный режим**: при открытии страницы на устройство загружается список ожидаемого. Без связи отметки сохраняются на устройстве и отправляются автоматически при восстановлении сети (или кнопкой).
- **Обнаружение учёт не меняет.** После завершения неотмеченное становится «не найдено». Решения по расхождениям: «принять фактическое» (новое местоположение и фактический пользователь — в карточку), «оставить учётное», «утрачено» (право списания), «без изменений». Каждое изменение — событие истории с номером инвентаризации.
- Отчёты: результаты (все строки, расхождения, по помещениям) и расхождения.

## Склад и поступление

- **Поступление** (документ): строки — тип или модель, наименование, количество, цена, гарантия, серийные номера; «Заказано» → «Принято». При приёмке на складе создаётся карточка на каждую единицу (статус «На складе», поставщик, документ приобретения, дата поступления, гарантия). Не больше 500 единиц в одном документе.
- **«Склад»**: число единиц по состояниям учёта (каждое открывает список), свободное и зарезервированное по моделям со стоимостью, комплектующие (установлены / свободны), последние поступления. Выдача со склада — документом «Выдача».
- **Комплектующие**: установка и снятие — связь «входит в состав» во вкладке «Состав и связи»; каждое событие («Состав») — в истории.

## Уведомления

«Настройки → Уведомления»: ежедневная сводка на почту (сервер почты — «Администрирование → Рассылки отчётов»): гарантия и лицензии на исходе, перемещения «в пути» и ремонты дольше срока, незавершённые инвентаризации, давно не обновлявшиеся сведения, компьютеры, пропавшие из KSC. Время и часовой пояс настраиваются; пустая сводка по умолчанию не отправляется; «Отправить сейчас» — проверка получателей.

## Серверная и сетевая инфраструктура

«Инвентаризация → Инфраструктура». Технические сведения поступают из существующих систем, организационные (назначение, сервис, ответственный, размещение) ведут администраторы в карточках; основная работа — разбор расхождений.

### Источники

Подключаются администратором («Источники»): тип, адрес, учётная запись или токен **только на чтение** (секрет хранится зашифрованным), проверка TLS, период синхронизации. «Проверить соединение» показывает число найденных объектов по видам и примеры, ничего не записывая. Каждый источник синхронизируется отдельным заданием: ошибка одного видна у него и не останавливает остальные.

| Тип | Что читается |
|---|---|
| Мониторинг (Zabbix, токен API) | узлы, адреса, доступность, включён ли мониторинг, группы |
| VMware vSphere (REST) | ВМ (CPU, память, диски, питание, SMBIOS UUID, MAC, гостевое имя и адрес), хосты, кластеры |
| Proxmox VE (токен, роль PVEAuditor) | узлы, ВМ и контейнеры (CPU, память, диски, SMBIOS UUID, MAC, адреса из конфигурации) |
| oVirt / zVirt (REST) | ВМ, хосты (серийный номер, UUID), кластеры |
| Hyper-V | выгрузка скриптом `scripts/windows/Export-KavHyperV.ps1` (только чтение): хосты и ВМ с BIOSGUID; загружается файлом |
| Реестр инфраструктуры (NetBox, токен) | устройства (серверы, сетевые), ВМ, IP-адреса, подсети, VLAN, площадки, стойки |
| Резервное копирование | список защищаемых объектов (JSON по HTTP или загрузка файла) с датой последней копии |
| Произвольный JSON (API провайдера) | список объектов по настраиваемым путям полей |

### Сопоставление и приоритет источников

- **Объект источника** хранится по своему идентификатору: повторная синхронизация обновляет его, изменения полей (CPU, память, диски, адреса, хост, питание, доступность) пишутся в историю конфигурации; исчезнувший помечается «нет в источнике» — не удаляется.
- **Сопоставление с учётной карточкой** — по убыванию надёжности: прежняя связь → SMBIOS UUID (оба порядка байт: у VMware первые три группы записаны иначе, чем видит гость) → серийный номер → MAC → имя (только однозначное; совпадение IP — подтверждение). Неоднозначное — «требует решения»: связать, создать карточку или «не связывать».
- **Новые серверы и ВМ** из систем виртуализации и реестра получают карточку автоматически (настройка источника); ВМ связывается с карточкой хоста («размещена на»).
- **Приоритет источников по полям** (по умолчанию): CPU, память, диски, питание, хост и кластер — система виртуализации; доступность и мониторинг — Zabbix; адреса — реестр инфраструктуры, затем виртуализация; площадка и стойка — реестр; резервное копирование — его система; назначение и ответственный — карточка; защита — KSC. Во вкладке карточки «Инфраструктура» у каждого поля — значение, источник, время и расхождения других источников.

### Сверка и решения

После каждой синхронизации сверка выявляет: объект есть в источнике, но нет в учёте; неоднозначное сопоставление; узел в мониторинге без учётной карточки; сервер не на мониторинге; мониторинг отключён; узел недоступен; нет резервного копирования; нет ответственного; не указано назначение; нет агента Kaspersky; исчез из источников; давно не обновлялся; один IP у нескольких объектов; выведенный из эксплуатации остался в мониторинге или резервном копировании; изменились IP, хост или конфигурация (на подтверждение).

Статусы: требует внимания, требует проверки, подтверждено, исправляется (ответственный, срок), устранено, принято как исключение (основание обязательно, можно указать срок). Не обнаруженное при очередной сверке закрывается «устранено», исключения сверка не трогает.

### Вывод из эксплуатации

Документ «Вывод из эксплуатации»: проверочный список (мониторинг снят, резервное копирование прекращено, адреса освобождены, связи сняты), при проведении — статус «Выведено из эксплуатации», связь ВМ с хостом снимается, история сохраняется. Действия во внешних системах выполняет администратор (раздел их только читает); если узел остался в мониторинге или резервном копировании, сверка покажет это расхождением.

### Сетевое обнаружение

«Инфраструктура → Сетевое обнаружение»: подсети или диапазоны → задание сканера Pentest с профилем `netscan` (своей очереди и запуска nmap нет). Сканер находит отвечающие адреса, проверяет короткий список портов (22, 23, 25, 53, 80, 88, 135, 139, 389, 443, 445, 515, 631, 902, 1433, 3306, 3389, 5432, 5900, 5985, 8006, 8080, 8443, 9100) и определяет службы; уязвимости не сопоставляются.

- **Кто запускает:** роль «Безопасность» и администратор; адреса — только внутри разрешённых сетей Pentest, с подтверждением, что сканирование согласовано (и отдельным — для большого охвата). Результаты видят все, кому открыта инвентаризация.
- **Тип узла** (`infra/netscan.classify`, оценка по сетевым признакам): принтер или МФУ (9100, 515, 631, ответ службы печати), сетевое устройство (ответы служб сетевого оборудования, Telnet без служб Windows), сервер (серверные службы, SSH, управление виртуализацией, веб-серверы), компьютер (службы Windows без серверных), иначе — «тип не определён». ОС — из ответов служб: без расширенных сетевых привилегий сканер не определяет MAC и отпечаток ОС.
- **Учёт:** готовое задание переносится в источник «Сетевое обнаружение» (создаётся сам): объект на IP-адрес, имя — из обратной записи DNS. Сопоставление с карточками — общее (имя), плюс по IP-адресу объекта другого источника, уже связанного с карточкой. Компьютер, сервер, принтер или сетевое устройство без карточки попадает в «Расхождения» («нет в учёте»); карточка создаётся из результатов одной кнопкой. Обнаружение охватывает часть сети и запускается вручную, поэтому отсутствие узла в следующем задании не считается исчезновением, а «давно не обновлялось» и повтор IP-адреса по нему не считаются.
- **Отчёт** «Сетевое обнаружение» (`infra_netscan`): все найденные узлы и «нет в учёте».

### Обзор, IP-адреса, стойки, отчёты

- Обзор: физические серверы, ВМ, хосты виртуализации и кластеры, сетевое оборудование, площадки, внешние ресурсы, активные и выведенные; без мониторинга, резервного копирования, ответственного, нет в учёте, недоступные, исчезнувшие, устаревшие; состояние источников. Отбор по площадке и ответственному; каждое число открывает список.
- IP-адреса: кто владеет адресом, в каких источниках, повторы; подсети и VLAN из реестра.
- Стойки: карта юнитов (юнит и высота задаются в карточке оборудования), свободные места.
- Отчёты (`quick_inv`): реестр серверной инфраструктуры (физические, ВМ, сеть — листами), гипервизоры и кластеры, IP-адреса и подсети, стойки, расхождения (по группам), изменения конфигурации, новые и исчезнувшие объекты, синхронизация источников, вывод из эксплуатации, состояние на дату, **периодическая проверка** (полнота, ответственные, мониторинг, копии, исключения — дважды в год вместо ручной проверки таблиц).

## Для разработчиков

- `backend/app/infra/`: `connectors.py` — коннекторы источников (разбор ответов — чистые функции, проверяются на образцах), `sync.py` — запись объектов и история, сопоставление, приоритет источников, сверка; `api/infra.py`; отчёты `reports/quick_infra.py`; страница `pages/inventory/InvInfra.tsx`.
- Инвентаризация со сканированием — `inventory/counting.py`, `api/inv_counts.py`, `pages/inventory/InvCounts.tsx` (камера — `InvCamera.tsx`).
- `backend/app/inventory/`:
  - `model.py` — словари: классы, состояния, виды, формы по умолчанию, встроенные справочники;
  - `core.py` — права и область учёта, номера, проверка и применение изменений, история, имена, вывод карточки;
  - `query.py` — отбор реестра (общий для списка, группировки, массовых операций и отчётов);
  - `docs.py` — этапы документов;
  - `printing.py` — печатные формы (структура, HTML, PDF, DOCX без внешних библиотек);
  - `labels.py` — этикетки PDF и ZPL;
  - `importer.py` — Excel и CSV;
  - `service.py` — worker: сверка связей с KSC, подсчёт использования лицензий.
- API:
  - `api/inv.py` — реестр, карточка, история, связь с KSC, сохранённые фильтры, вложения, импорт;
  - `api/inv_dirs.py` — местоположения, справочники, свойства, сотрудники;
  - `api/inv_docs.py` — документы, печать, этикетки;
  - `api/inv_lic.py` — лицензии.
- Отчёт — `reports/quick_inv.py`. Настройки — группа `inventory` (`InventorySettings`). Запрос к KSC для лицензий — `queries.LIC_HOSTS`.
- Интерфейс — `frontend/src/pages/inventory/`: оболочка `InvApp.tsx` и навигация `INV_NAV` в `navModel.ts`. Блок в карточке компьютера — `components/InvHostBlock.tsx`.
- Тесты — `tests/test_inventory.py`.
