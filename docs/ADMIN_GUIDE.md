# Руководство администратора

## Первый вход

Войдите локальным администратором (`admin`, пароль из вывода установщика) и смените пароль. Локальный администратор не зависит от LDAP и остаётся резервным входом.

## Источники KSC

Администрирование → Источники KSC → «Добавить источник».

| Поле | Значение |
|---|---|
| Название | произвольное, например «Kaspersky 01»: его видят пользователи в переключателе |
| Сервер, порт | SQL Server базы Сервера администрирования; порт 1433 по умолчанию; именованный экземпляр — по его TCP-порту |
| База данных | имя базы KSC (по умолчанию `KAV`); на одном SQL Server может быть несколько баз разных Серверов администрирования — каждая добавляется отдельным источником |
| Шифрование | «обязательно» требует TLS; «доверять сертификату сервера» нужно для самоподписанных сертификатов SQL Server |
| Тип авторизации | SQL Server (логин/пароль) или Windows (`DOMAIN\user`, NTLM) |
| Тайм-ауты | подключения и запроса; увеличьте тайм-аут запроса для больших баз |

«Проверить подключение» выполняет диагностику: соединение, версия и редакция SQL Server, база, наличие объектов KSC для каждой функции (компьютеры, реестр ПО, защита, уязвимости, события), роли учётной записи (предупреждение, если есть права на запись), версия KSC, пробное чтение. Результат хранится у источника и виден на главной и в состоянии системы.

Если каких-то объектов нет (другая версия KSC), соответствующая функция сообщит о несовместимости, остальные работают. Приложение никогда не меняет базу KSC.

Переключатель в верхней панели выбирает источник для всех разделов; данные разных источников не смешиваются, в каждом отчёте сохраняется название источника и время получения данных.

## Пользователи и роли

| Роль | Права |
|---|---|
| Администратор | всё: источники, пользователи, LDAP, настройки, обновления, журналы |
| Аналитик | данные всех разрешённых источников, формирование отчётов, сценарии аудита, шаблоны |
| Просмотр | разделы и готовые отчёты по разрешённым источникам без создания |

Права проверяются на backend при каждом запросе. Для аналитиков и пользователей просмотра можно ограничить список источников («Все источники» выключить и отметить нужные).

Локальные пользователи создаются здесь же; пользователи LDAP появляются после первого входа, их роль определяется группами (см. ниже).

## LDAP / LDAPS

Администрирование → LDAP. Укажите сервер, протокол (LDAPS рекомендуется), Base DN, сервисную учётную запись (только чтение) и пароль, фильтр пользователя (`{login}` заменяется логином), группы ролей (DN). Включите «Вход по LDAP», сохраните и нажмите «Проверить подключение»: соединение → вход сервисной записи → чтение Base DN; при указании тестового логина и пароля проверяется вход пользователя и вычисляется его роль.

Правила роли: администратор, если пользователь входит в группу администраторов; иначе аналитик по группе аналитиков; иначе просмотр, если он входит в группу просмотра — или если группа просмотра не задана, но задана хотя бы одна из первых двух. Без настроенных групп вход по LDAP невозможен. Вложенные группы учитываются для Active Directory.

Подробнее — [docs/LDAP.md](LDAP.md).

## Общие настройки

- **Порог активности** (по умолчанию 7 суток): компьютер считается актуальным, если подключался к KSC за это время. Варианты 1/3/7/14/30 суток или произвольное число. В разделах и отчётах порог можно переопределить и включить все компьютеры; отчёт показывает, сколько компьютеров исключено из-за отсутствия связи. Статус активности отражает давность связи с KSC, а не доступность компьютера сейчас.
- Срок хранения отчётов и журнала событий.
- Ограничения отчётов: предел строк, исключение кластеров и подчинённых серверов (`bIsSlaveServer = 1`).

## Программное обеспечение

- **Реестр KSC** — записи реестра приложений как в консоли: название, версия, производитель, платформа, число установок и уникальных компьютеров. Поиск по части названия, производителю, версии. Кнопка «Компьютеры» показывает устройства с этой записью.
- **Группировка** — продукт из множества пакетов объединяется по веткам major.minor по правилу (встроенное — PHP). Строка «версия не определена» — пакеты, по которым ветку нельзя установить достоверно (метапакеты с эпохой дистрибутива). «Пакеты» раскрывает исходные записи и показывает, по какому полю взята версия.
- Отметьте версии или ветки → «Найти компьютеры»: список с фильтром активности, число установок и уникальных компьютеров; оттуда — «Сформировать отчёт» или «Сохранить как сценарий аудита» (CVE, уровень, описание). Сохранённые сценарии — пользовательские критерии, они показываются отдельно от уязвимостей, подтверждённых KSC.

Правила группировки для других продуктов добавляются в Администрирование → Правила группировки.

## Компьютеры

Список с фильтрами по имени, группе, ОС и активности; карточка компьютера: сведения, статус KSC с причинами, продукты Kaspersky с версиями и датой баз, установленное ПО.

## Отчёты

Конструктор: тип (компьютеры с программами / компьютеры и активность), правило и ветки или шаблон названия, диапазон версий (dpkg: «7.x» = от 7 и ниже 8), платформа, группа, порог активности, включение компьютеров без связи. Отчёт формируется в фоне (воркер), его можно отменить; готовый отчёт — просмотр с сортировкой и фильтром, XLSX с листами «Установки», «Версии», «Компьютеры», «Параметры» и CSV. Отчёт можно повторить; условия можно сохранить шаблоном.

## Журналы и состояние

- **Журнал действий** — кто, что и когда: входы, настройки, источники, отчёты.
- **Журнал событий** — ошибки, проверки и запросы к источникам, формирование отчётов, с длительностью; выгрузка CSV.
- **Состояние системы** — backend, внутренняя база, воркер отчётов, помощник обновлений, диагностика и лёгкая проверка доступности источников по кнопке.

Секреты и SQL с параметрами в журналы не попадают.
