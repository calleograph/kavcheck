# Руководство администратора

## Первый вход

Войдите локальным администратором (`admin`, пароль из вывода установщика) и смените пароль. Локальный администратор не зависит от LDAP и остаётся резервным входом.

## Источники KSC

Администрирование → Источники KSC → «Добавить источник». На виду — название, SQL Server, порт, база и учётная запись; шифрование, тайм-ауты и выключение источника — в блоке «Дополнительно» (значения по умолчанию подходят для большинства установок). «Сохранить и проверить» сразу выполняет диагностику.

| Поле | Значение |
|---|---|
| Название | произвольное, например «Kaspersky 01»: его видят пользователи в переключателе |
| Сервер, порт | SQL Server базы Сервера администрирования; порт 1433 по умолчанию; именованный экземпляр — по его TCP-порту |
| База данных | имя базы KSC (по умолчанию `KAV`); на одном SQL Server может быть несколько баз разных Серверов администрирования — каждая добавляется отдельным источником |
| Шифрование | «обязательно» требует TLS; «доверять сертификату сервера» нужно для самоподписанных сертификатов SQL Server |
| Тип авторизации | SQL Server (логин/пароль) или Windows (`DOMAIN\user`, NTLM) |
| Тайм-ауты | подключения и запроса; увеличьте тайм-аут запроса для больших баз |

«Проверить» в карточке источника (и «Сохранить и проверить» в форме) выполняет диагностику: соединение, версия и редакция SQL Server, база, наличие объектов KSC для каждой функции (компьютеры, реестр ПО, защита, уязвимости, события), роли учётной записи (предупреждение, если есть права на запись), версия KSC, пробное чтение. Результат хранится у источника и виден на главной и в состоянии системы.

Если каких-то объектов нет (другая версия KSC), соответствующий раздел сообщает о несовместимости, остальные работают. Приложение никогда не меняет базу KSC.

Переключатель в верхней панели выбирает источник для разделов и запоминается для каждого пользователя. Проверку версий можно выполнить сразу по нескольким источникам: источник — часть каждой строки результата.

## Пользователи и роли

| Роль | Права |
|---|---|
| Администратор | всё: источники, пользователи, LDAPS, настройки, обновления, журналы |
| Аналитик | данные разрешённых источников, проверки версий и отчёты, сохранённые проверки |
| Просмотр | разделы и готовые отчёты по разрешённым источникам без создания |

Права проверяются на backend при каждом запросе. Аналитикам и пользователям просмотра можно ограничить список источников. Локальные пользователи создаются в разделе «Пользователи»; пользователи каталога появляются после первого входа, их роль и источники задают правила доступа LDAP.

### Второй фактор

Администрирование → Пользователи → «Двухфакторная аутентификация». Политики: отключён, по желанию, обязателен администраторам, обязателен всем, обязателен членам групп каталога (DN групп). Пользователь подключает приложение-аутентификатор (TOTP, 6 цифр, 30 секунд) в разделе «Безопасность входа» меню пользователя и получает 10 одноразовых резервных кодов. Если политика требует второй фактор, а он не подключён, после входа открывается только страница подключения. Администратор может сбросить второй фактор пользователя (например, при потере телефона); действие записывается в журнал.

## LDAPS

Администрирование → LDAPS: подключения к доменам, сертификаты ЦС, правила доступа по группам, проверка подключения и проверка входа пользователя. Доменные пользователи входят по имени учётной записи без домена (например, `ivan.petrov`); если имя есть в нескольких доменах, на странице входа выбирается домен. Подробно — [docs/LDAP.md](LDAP.md).

## Общие настройки

- **Показывать компьютеры, активные за последние N суток** (по умолчанию 30). Компьютеры, не подключавшиеся к KSC дольше, скрыты в рабочих разделах (каталог, реестр, компьютеры, уязвимости, состояние защиты, проверки версий); под списками указано, сколько скрыто, и есть кнопка «Показать все». Активность — давность связи Агента с KSC, а не доступность компьютера сейчас.
- Срок хранения отчётов и журнала событий.
- Ограничения отчётов: предел строк, исключение кластеров и подчинённых серверов (`bIsSlaveServer = 1`).

## Программы

- **Каталог** — записи реестра KSC, объединённые в продукты: Google Chrome, Firefox, Java, PHP, Python, OpenSSL и другие; производитель, ветки, версии, число компьютеров. Связанные пакеты и компоненты собираются в **семейства**: основной продукт и компоненты, название которых начинается с его названия (php-xml, php-pear → PHP; Proofing Tools → Microsoft Office; тонкий клиент → 1С:Предприятие). Без поиска показаны основные продукты, «N компонентов» раскрывает состав; в поиске видны все совпадения с названием семейства. Число компьютеров открывает их список в боковой панели. Карточка продукта показывает ветки и версии («спектр версий»); щелчок по версии или ветке — компьютеры в боковой панели (компьютер, IP, онлайн, установленная версия, ОС, группа, подключение к KSC); «Назад» из карточки компьютера возвращает к той же панели.
- **Выбор программ.** Отметки в каталоге: у основного продукта семейства — весь набор, у компонента — только он. Выбор хранится для источника и не теряется при переходах; панель внизу — «Проверить версии» (конструктор с выбранными программами; семейство — один пункт с одним условием) и «Отчёт по установкам» (все версии выбранных программ на компьютерах, XLSX).
- **Производители** — продукты по производителям.
- **Реестр KSC** — исходные записи реестра приложений, как в консоли KSC.

Каталог строится фоновой службой (worker) после первого подключения источника, при изменении реестра (проверка каждые 15 минут), раз в 12 часов и по кнопке. Ошибочную группировку исправляют в Администрирование → Каталог программ: объединить продукты, выделить записи в отдельный продукт, переименовать. Ручные правки сохраняются при обновлениях каталога и версии приложения.

## Проверка версий

Раздел «Отчёты» (или «Проверить» у программы в каталоге). Выберите программу и версию, ниже которой она устарела — новейшая версия из каталога подставляется щелчком, — затем «Найти устаревшие версии» (компьютеры сразу на странице) или «Сформировать XLSX» (фоновый отчёт с ходом выполнения и отменой). В одной проверке может быть несколько программ и несколько источников. «Дополнительные условия»: целевая версия, другие условия (не выше, равна, диапазон), платформа, исключения версий и веток, отбор по названию записи (LIKE, регулярное выражение). «Какие компьютеры учитывать»: давно не подключавшиеся, свой порог активности, группа администрирования. Версии сравниваются по правилам продукта: пакеты Linux — как dpkg, программы Windows — по числам, Java и Python Windows — с приведением нумерации (8.0.4010.7 → 8.0.401).

Пункт проверки может охватывать несколько продуктов каталога (семейство или выбранные компоненты): условие одно, каждая запись реестра сравнивается по схеме своего продукта. В результате у каждой программы — «Найдено записей реестра»: какие пакеты и версии найдены и какие подходят под условие; в строках — точная запись реестра, версия и продукт каталога. В XLSX — листы «Итог», «Компьютеры», «Версии», «Найденные пакеты», «Параметры». Результат быстрой проверки и строки отчёта — непрерывный список.

«Сохранить проверку» запоминает условия; сохранённые проверки запускаются одной кнопкой и видны в разделе «Уязвимости» на вкладке «Проверки версий». Результат проверки — компьютеры, подходящие под условие, а не подтверждённые уязвимости.

## Списки

Все списки — один непрерывный список без страниц: строки подгружаются с сервера порциями при прокрутке, поиск, фильтры и сортировка выполняются на сервере по всему набору. После карточки компьютера или продукта «Назад» возвращает к тому же месту списка с теми же фильтрами.

## Поиск

Поле поиска в верхней панели (`/` или Ctrl+K) ищет в текущем источнике компьютеры по имени и DNS-имени и программы каталога; Enter открывает карточку, «Все компьютеры с …» и «Все программы с …» — списки разделов с этим запросом.

## Компьютеры

Список с фильтрами по имени, группе, ОС и активности. Карточка компьютера: сведения, статус KSC с причинами, проблемы защиты, продукты Kaspersky с версиями и датой баз; вкладки «Установленное ПО», «Уязвимости», «События безопасности» (за 30 суток).

## Уязвимости

Уязвимости, найденные KSC: компьютеры по опасности (сначала с критическими), уязвимые программы, карточка компьютера с CVE, KB и наличием исправления. Поиск по компьютеру, программе, CVE и группе; фильтр по уровню и наличию исправления. Сводка кэшируется на срок `CACHE_TTL_SECONDS`; «Обновить» перечитывает данные KSC.

## Состояние защиты

Переключатель **«Только онлайн»** (включён по умолчанию): числа проблем, список и поиск — только по устройствам, которые KSC сейчас видит в сети. «Онлайн» — это флаг KSC «видимо в сети», а не давность подключения: компьютер, подключавшийся за 30 суток, может быть выключен. Колонка «Онлайн»: «в сети», «не в сети» (когда KSC последний раз видел устройство и от какой даты сведения о защите), «нет данных» (KSC не передал флаг). Без «Только онлайн» видны все активные устройства. Тот же статус — в списке компьютеров и карточке компьютера.

Проблемы по активным компьютерам, по важности: нет антивируса (нет защитного продукта Kaspersky или KSC не получал о нём сведений), защита не работает (постоянная защита остановлена, приостановлена, в сбое, или продукт не запущен), невылеченные объекты, устаревшие базы (порог 1, 3 или 7 суток), лицензия истекла (по статусу KSC), нет свежей полной проверки (порог 7, 30 или 90 суток), требуется перезагрузка. Щелчок по проблеме или версии фильтрует список компьютеров и прокручивает к нему. «Версии продуктов» — сколько компьютеров на каждой сборке KES, KESL и Агента администрирования; щелчок по версии показывает компьютеры с ней. «Причины статуса в KSC» — распределение причин, которые указал сам KSC.

Сведения берутся из последних отчётов Агентов администрирования; набор по источнику кэшируется, пороги и фильтры не нагружают SQL Server.

## События безопасности

Журнал событий KSC за сутки, 7 или 30 суток: обнаружено угроз, не вылечено, обработано (удалено, вылечено, в карантине), сетевые атаки; динамика по часам или суткам; компьютеры и угрозы с наибольшим числом событий; журнал обнаружений с поиском по компьютеру, угрозе, объекту и пользователю. Запросы всегда ограничены периодом и типами обнаружений (журнал KSC — самая крупная таблица базы). События удалённых из KSC устройств показываются как «удалённое устройство».

Журнал содержит имена пользователей и пути к файлам — персональные данные. Доступ к разделу — у всех ролей с доступом к источнику.

## Журналы и состояние

- **Журнал действий** — кто, что и когда: входы, настройки, источники, отчёты, LDAP, второй фактор.
- **Журнал событий** — ошибки и предупреждения приложения и фоновых задач, проверки источников и каталога, формирование отчётов; фильтр по компоненту, уровню и периоду; выгрузка CSV.
- **Состояние системы** — компоненты (backend, внутренняя база, worker, помощник обновлений), процессор и память, диски, размер базы, отчётов, резервных копий и образов, источники KSC и каталог, последние ошибки, история обновлений, безопасность (HTTPS, cookie, ключ шифрования, политика второго фактора).

Секреты и SQL с параметрами в журналы не попадают.
