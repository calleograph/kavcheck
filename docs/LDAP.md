# Настройка LDAPS / Active Directory

Администрирование → LDAPS. Вкладки: «Подключения» (по одному на домен или каталог), «Сертификаты CA», «Правила доступа», «Проверка входа».

Соединение — только LDAPS (порт 636) или STARTTLS (389); шифрование и проверка сертификата сервера обязательны, пароль без TLS не передаётся. Переходы по ссылкам (referrals) на другие серверы отключены.

## Подключения

| Поле | Active Directory | Другие каталоги |
|---|---|---|
| Название | «Основной домен», «Филиал» — видно в журналах и диагностике | |
| Адрес | `ldaps://dc01.example.local:636` или имя домена `example.local` (глобальный каталог — порт 3269) | LDAPS 636 или STARTTLS 389 |
| Версия LDAP, тайм-аут | 3; 5 секунд | |
| Base DN | `DC=example,DC=local` | корень поиска пользователей и групп |
| DNS-домен | `example.local` — различает пользователей разных доменов с одинаковым именем; принимается и вход вида `user@example.local` | |
| NetBIOS-имя | `EXAMPLE` — необязательно; принимается вход вида `EXAMPLE\user` | |
| Сервисная учётная запись | `CN=svc-kavcheck,OU=Service,DC=example,DC=local` или `svc-kavcheck@example.local`, только чтение | DN сервисной записи |
| Атрибуты | логин `sAMAccountName`, имя `displayName`, почта `mail` | `uid`, `cn`, `mail` |
| Фильтр пользователей | `(&(objectCategory=person)(objectClass=user))` | например `(objectClass=inetOrgPerson)` |
| Вложенные группы | включить (LDAP_MATCHING_RULE_IN_CHAIN) | выключить, если каталог не поддерживает; используются `memberOf` и группы `groupOfNames`/`groupOfUniqueNames`/`posixGroup` |

Подключение можно выключить, не удаляя; одно из включённых — основное. Пароль сервисной записи хранится зашифрованным (`APP_MASTER_KEY`), в форму не возвращается; «Удалить учётные данные» стирает его и выключает подключение.

## Вход пользователя

Пользователь вводит только имя своей учётной записи (sAMAccountName), например `ivan.petrov`, — без домена. Допустимы буквы, цифры, точка, дефис и подчёркивание.

1. Сначала проверяется локальная учётная запись KAV Checker с таким именем (локальный администратор работает при любом состоянии LDAPS).
2. Имя ищется сервисной учётной записью во всех включённых подключениях (атрибут логина и фильтр пользователей подключения).
3. Найдено в одном домене — пароль проверяется входом от имени найденного DN в этом домене. Найдено в нескольких — вход не выполняется, на странице входа появляется выбор домена (он виден, когда включено больше одного подключения); выбранный домен — единственный, где ищется пользователь. Так исключён вход в «чужой» домен с тем же именем.
4. Читаются группы (с вложенными), применяются правила доступа, при политике второго фактора запрашивается код, открывается сессия.

Вход вида `EXAMPLE\user` и `user@example.local` по-прежнему принимается и сразу выбирает подключение по NetBIOS- или DNS-имени. Пользователи разных доменов с одинаковым именем — разные пользователи KAV Checker: второй получает имя `user@домен`; локальная учётная запись с тем же именем не затрагивается.

Пользователь при ошибке видит общее сообщение («Неверный логин или пароль»). Точная причина — в Журнале событий (компонент «Вход») и Журнале действий: пользователь не найден (с фильтром и Base DN), несколько записей, ошибка поиска (Base DN не найден, ответ-ссылка на другой сервер, нет прав), контроллер отклонил пароль (с DN), нет разрешённой группы, учётная запись отключена или заблокирована.

## Сертификаты CA

Проверка сертификата сервера LDAP всегда включена. Если сертификат выдан корпоративным ЦС, загрузите корневой и, при необходимости, промежуточные сертификаты: файл PEM или DER либо вставленный текст PEM, можно несколько в одном файле. Перед добавлением показываются субъект, издатель, серийный номер, отпечаток SHA-256 и срок действия; просроченные и не являющиеся ЦС сертификаты отмечаются. Файл с закрытым ключом не принимается. Без загруженных сертификатов используется системное хранилище ЦС образа.

## Правила доступа

Правило: группа каталога (DN) → роль (администратор, аналитик, просмотр) и источники KSC (все или выбранные), для всех подключений или одного. Группу можно найти поиском по каталогу. Если пользователь входит в несколько групп с правилами, он получает старшую роль и объединение источников. Пользователь без подходящего правила не допускается.

Вкладка «Проверка входа» показывает для имени пользователя, найден ли он и в каком домене, его группы, сработавшие правила, итоговую роль и источники; с паролем — ещё и проверку пароля контроллером домена (см. «Диагностика»).

Отключение учётной записи в каталоге или исключение из групп блокирует вход при следующей попытке; отключение в KAV Checker (Пользователи) — тоже, независимо от каталога.

## Диагностика

**Проверка подключения** (кнопка «Проверить» у подключения) — только контроллер домена: параметры → DNS → TCP → TLS и цепочка сертификатов → вход сервисной записи → чтение Base DN. Останавливается на первой ошибке с объяснением.

**Проверка входа** (вкладка) — тот же путь, что при настоящем входе, но без открытия сессии: имя → поиск в каждом подключении (найден, не найден, ошибка поиска) → выбор домена → пароль (если указан) → группы → правила доступа → второй фактор. Пароль не сохраняется и не пишется в журналы; проверка записывается в журнал действий.

Типичные ошибки: «сертификат не прошёл проверку» — загрузите корневой (и промежуточный) сертификат ЦС или проверьте, что имя в адресе совпадает с именем в сертификате сервера; «неверные учётные данные сервисной записи»; «Base DN не найден»; «Base DN обслуживает другой сервер» — укажите контроллер этого домена; «пользователь не найден» — проверьте фильтр пользователей, атрибут логина и Base DN (фильтр в стиле 0.1.0 с `{login}` тоже поддерживается); «контроллер домена отклонил пароль».

## Переход с 0.1.0

Единственное подключение 0.1.0 при первом запуске 0.2.0 переносится в подключение «Основной домен», его сертификат ЦС — в список сертификатов, группы администраторов, аналитиков и просмотра — в правила доступа. Проверьте перенесённые правила и укажите DNS-домен и NetBIOS-имя.
