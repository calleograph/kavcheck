# База уязвимостей

Модуль «База уязвимостей» (0.4.0) собирает сведения об уязвимостях из независимых внешних баз, хранит их локально и проверяет, затрагивают ли они ПО, установленное в подключённых KSC. Результат — **потенциальные** уязвимости; уязвимости, подтверждённые самим KSC (`vapm`), остаются в разделе «Уязвимости» и никогда не смешиваются с ними.

## Для администратора

**Администрирование → База уязвимостей.** Одна кнопка «Включить все источники и загрузить» (или переключатель у конкретного источника) включает источник с настройками по умолчанию и **сразу ставит первую загрузку в очередь**: фоновая служба выполняет её, строит локальный поиск и дальше обновляет данные по расписанию (каждый час … раз в неделю; после ошибки повтор через 30 минут). Учётные данные и ручная настройка не нужны: все четыре источника публичные. Для каждого источника показаны: состояние и **текущий этап** (скачано X из Y МБ, разбор, проверка, замена), число записей, дата последней успешной загрузки, длительность, **используемый канал**, **попытки последней загрузки** (канал → результат → время → причина) и история загрузок; кнопка «Обновить сейчас».

| Источник | Каналы (по порядку; при ошибке — следующий) | Первая загрузка | Обновления |
|---|---|---|---|
| CISA KEV | 1) cisa.gov (JSON); 2) GitHub `cisagov/kev-data` (JSON) | весь каталог (≈1,5 тыс.) в новое поколение | то же, с проверкой и заменой |
| NVD (NIST) | 1) официальные ленты JSON 2.0 `nvd.nist.gov/feeds/json/cve/2.0/nvdcve-2.0-ГОД.json.gz` с проверкой SHA-256 по `.meta`; 2) API 2.0 (запасной: окна по дате, 5 запросов за 30 с без ключа, 50 с ключом) | ленты за N лет (по умолчанию 3; 1…30), потоково, в новое поколение | лента «изменённые» (последние 8 суток), если с прошлой загрузки ≤ 7 суток, иначе ленты текущего года; более ранние годы догружаются при увеличении глубины |
| OSV | архивы экосистем `storage.googleapis.com/osv-vulnerabilities/<экосистема>/all.zip` (по умолчанию Debian, Alpine, Red Hat, AlmaLinux, Rocky Linux ≈ 120 МБ; Ubuntu ≈ 750 МБ, npm ≈ 210 МБ; 43 экосистемы на выбор; «вся база» — 2,8 ГБ) | архивы выбранных экосистем в новое поколение | `modified_id.csv` экосистемы (потоком до первой старой строки) → только изменённые записи (`<id>.json`, запасной путь — `api.osv.dev`); при > 4000 изменений или смене состава экосистем — перезагрузка архивом |
| БДУ ФСТЭК | 1) `https://bdu.fstec.ru/files/documents/vulxml.zip` (проверка TLS по сертификатам Минцифры, условный запрос `If-None-Match`/`If-Modified-Since`); 2) файл XML/ZIP, загруженный вручную | выгрузка целиком (≈98 тыс. записей) в новое поколение | то же; если файл на сайте не изменился (HTTP 304) — загрузка пропускается |

**Надёжность загрузки.**

* Первая загрузка и пересборка пишутся в **новое поколение** (отдельные строки, невидимые для поиска) и подменяют действующее только после проверки: непустое и не меньше половины прежнего. Повреждённый, оборванный или неполный файл (контрольная сумма ленты NVD не совпала, архив не открывается, XML оборван, получено меньше `Content-Length`, мало записей) отклоняется целиком, действующая база не меняется, недозагруженное поколение удаляется. Предыдущая полная копия источника хранится для отката («Вернуть предыдущую копию»).
* Обновления по изменениям пишут каждую запись целиком в своей транзакции; курсор (до какого момента загружено) сдвигается только после успешной загрузки.
* Скачивание — потоком в файл на томе данных (`DATA_ROOT/…/vdb/tmp`, а не в слое контейнера); память не растёт с размером файла (ленты NVD и XML БДУ разбираются потоком: измерено ≈35 МБ при разборе 666 МБ XML БДУ). Перед скачиванием проверяется свободное место по `Content-Length` (нужно размер × 1,2 + 256 МБ), временные файлы удаляются сразу после разбора и при любой ошибке; остатки старых загрузок убираются при старте.
* Повторы с задержкой при 429/5xx, тайм-ауты соединения и чтения, проверка сертификатов всегда включена (отключается только администратором явно, для БДУ), уважаются настройки прокси окружения; запросы к NVD API укладываются в лимиты. CAPTCHA, авторизация и технические ограничения сайтов не обходятся.
* Без интернета приложение работает по последней успешной копии: поиск, карточки, сопоставление и отчёты не зависят от доступности источников; ошибка загрузки показывает причину по каналам, данные остаются.

**Расписание и место на диске.** Интервалы по умолчанию: CISA KEV — 12 ч, NVD — 6 ч (лента «изменённые» обновляется у NIST раз в сутки), OSV — 24 ч, БДУ — 24 ч (если файл на сайте не менялся, загрузка пропускается за секунды); меняются в настройках источника. Кнопки: «Обновить сейчас» у источника и «Обновить все сейчас» вверху. База не разрастается без нужды:

* у БДУ, NVD и OSV после успешной проверки и замены хранится **одна** копия (предыдущая удаляется; у крошечного KEV — две, для отката); недозагруженные поколения удаляются при ошибке и при старте службы;
* записи, отозванные источником (NVD `Rejected`, OSV `withdrawn`), удаляются при обновлении вместе со сводкой;
* временные архивы и ленты удаляются сразу после разбора и при любой ошибке; остатки прерванных загрузок — при старте;
* история загрузок — 60 последних записей на источник; пересборка объектов PostgreSQL выполняется автовакуумом;
* перед плановой загрузкой проверяется свободное место (порог 1 ГБ, `VDB_MIN_FREE_MB`): при нехватке загрузка не начинается, а в интерфейсе и журнале событий — понятная причина; вверху раздела видны занятое базой уязвимостей место, временные файлы и свободное место на диске.

**БДУ ФСТЭК: что выяснено.** `bdu.fstec.ru` доступен по HTTPS; официальная выгрузка — `https://bdu.fstec.ru/files/documents/vulxml.zip` (ZIP с `export/vulxml.xml`, ≈34 МБ, ≈666 МБ в распакованном виде, ≈98 тыс. записей `<vul>`; обновляется на сайте несколько раз в месяц, `Last-Modified`/`ETag` отдаются). Стандартные хранилища сертификатов её не проверяют: сертификат `*.fstec.ru` выдан «Russian Trusted Sub CA» Минцифры России, а сервер не присылает промежуточный сертификат (ошибка `unable to get local issuer certificate`). Поэтому вместе с приложением поставляются корневой «Russian Trusted Root CA» (SHA-256 `D26D2D02…CF31`, срок до 2032) и промежуточные сертификаты (`app/vdb/ca/russian_trusted_chain.pem`, отпечатки проверяются тестом); они применяются **только** к соединениям с источником БДУ и не попадают в общее хранилище доверия; отключить можно переключателем в настройках источника. Если сервер находится за пределами РФ и сайт недоступен (блокировка по адресу), скачайте файл на другом компьютере и загрузите кнопкой «Загрузить файл выгрузки» (XML или ZIP, до 400 МБ): разбор и проверки те же.

| Источник | Канал | Записей | Время | Замечания |
|---|---|---|---|---|
| БДУ ФСТЭК | сайт, проверенный TLS | 98 400 (855 тыс. строк затронутого ПО) | первая загрузка ≈ 10 мин (скачивание 34 МБ + разбор 666 МБ XML + запись); повтор без изменений на сайте — 0 с (HTTP 304) | память воркера ≈ 35 МБ при разборе |
| NVD | ленты 2.0 за 3 года | 161 376 | ≈ 12 мин; обновление лентой «изменённые» ≈ 3 мин (23 тыс. прочитано, 20 новых) | годовая лента 25–30 МБ gz |
| OSV | архивы Debian, Ubuntu, Alpine | 144 747 | ≈ 32 мин (Ubuntu — 755 МБ); обновление по `modified_id.csv` — 1–3 с | архив удаляется после разбора |
| CISA KEV | cisa.gov | 1 756 | 6–9 с | запасной канал GitHub проверен тестом |

Итого в единой базе 238 124 уязвимости (по CVE и псевдонимам БДУ/GHSA/DEBIAN-… объединены записи разных источников), 225 424 с оценкой CVSS; индексы и таблицы ≈ 1,5 ГБ. Проверено на реальных данных: поиск `CVE-2024-3094` (xz) находит запись трёх источников (BDU+NVD+OSV) за 150 мс, `CVE-2026-*` — 79 тыс. за 0,6 с, `*sql*` — 14 тыс. за 0,2 с, версия программы (`log4j` + `2.14.1`) — 20 мс; выключенная сеть (прокси в никуда): все источники ответили понятной ошибкой с попытками по каналам, число записей в базе осталось прежним, поиск работал; прерывание службы посреди загрузки: статус «выполняется» снимается при старте, недозагруженное поколение удаляется. Цепочка до компьютеров: CVE-2024-0519 (Chrome < 120.0.6099.224) → установленный Chrome 120.0.6099.130 на компьютере тестового KSC → «Подтверждено источником, версия < 120.0.6099.224» → XLSX и HTML. Linux-пакеты (PHP из Debian/Ubuntu) помечаются «требуется уточнение»: исправление могло быть перенесено в версию дистрибутива.

**Что осталось ограничением.** (1) Обновления NVD без ключа API для запасного канала и дополнений идут медленно (5 запросов за 30 с): эксплуатируемые CVE старше глубины истории догружаются по 20 за запуск; увеличьте глубину истории или задайте ключ. (2) Свободный текст версий БДУ (≈ 26 % строк до улучшения разбора, теперь меньше: «от X до Y», «… включительно», «N LTS» разбираются) остаётся «требуется уточнение», если его нельзя сравнить числом (например «Server 10», названия выпусков). (3) Ленты NVD обновляются на стороне NIST раз в сутки; для более свежих данных используйте запасной канал API. (4) Сайт БДУ может блокировать адреса вне РФ: тогда работает ручная загрузка файла.

## Оценка опасности (CVSS)

Каждая запись источника хранит **все** оценки CVSS (таблица `vdb_records`, столбец `scores`): версия методики (4.0, 3.1, 3.0, 2.0), балл 0.0–10.0, вектор, уровень, кто выставил, источник, дата обновления записи. Откуда берутся оценки:

| Источник | Что содержит |
|---|---|
| NVD | все оценки `cvssMetricV40/V31/V30/V2`: оценка аналитиков NVD (`primary`) и оценки поставщиков (CNA, `secondary`) |
| БДУ ФСТЭК | CVSS 3.0 (`cvss3`) и CVSS 2.0 (`cvss`) из карточки |
| OSV | только вектор: для CVSS 3.x балл вычисляется по вектору по спецификации FIRST (помечено «вычислена по вектору»); для 4.0 и 2.0 вычисление не поддерживается — оценки нет |
| CISA KEV | оценок нет |

**Основная оценка** (порядок выбора, один на все разделы; остальные оценки остаются и показываются в карточке):

1. CVSS 3.x и 4.0 важнее 2.0 (2.0 — только если других нет).
2. Оценка аналитиков NVD или БДУ (`primary`) важнее оценки поставщика (CNA) и вычисленной по вектору. Иначе оценки CVSS 4.0 от поставщиков вытесняли бы оценку NVD по 3.1.
3. Из равных — более новая методика: 4.0, затем 3.1, затем 3.0.
4. Затем источник: NVD, БДУ, OSV; затем больший балл.

**Уровни** (CVSS 3.x и 4.0): None — 0.0, Low (низкая) — 0.1–3.9, Medium (средняя) — 4.0–6.9, High (высокая) — 7.0–8.9, Critical (критическая) — 9.0–10.0. У CVSS 2.0 уровней None и Critical нет (High — от 7.0). Уровень всегда выводится из балла основной оценки и её методики.

**Нет данных.** Если достоверной оценки нет (NVD ещё не проанализировал запись, источник не дал балл), в таблице и карточке показано «Нет данных». Ноль не подставляется, оценка по названию CVE не вычисляется; недостоверные значения (не число, вне 0–10, неизвестная методика) отбрасываются. Если числовой оценки нет, но источник назвал уровень (например, БДУ — «высокий»), он показан со звёздочкой «по данным источника» и не попадает в фильтр по баллам. Оценка 0.0 — это уровень None, а не отсутствие оценки.

**Таблица и фильтры.** Столбцы «CVSS» (балл и версия методики) и «Критичность». Сортировка по баллу — щелчок по заголовку «CVSS» (сначала самые опасные; без оценки — всегда в конце). Фильтр «CVSS»: готовые диапазоны (критическая 9.0–10.0, высокая 7.0–8.9, средняя 4.0–6.9, низкая 0.1–3.9, нет данных) и свои границы «от/до» (включительно). В API: `score_min`, `score_max`, `no_score`, `sort=score` для `/api/v1/vdb/vulns` и `/api/v1/vdb/findings`.

**Карточка.** Балл, уровень, версия методики, источник оценки и кто её выставил, вектор, дата обновления, ссылка на первоисточник (страница в NVD, БДУ или OSV), список остальных оценок.

**Прежние записи.** Миграция `0006_cvss_scores` добавляет столбцы. При первом запуске воркер один раз преобразует прежние баллы в список оценок (версия определяется по вектору; если определить нельзя — оценка считается недостоверной и не показывается). Потом при ближайшей загрузке NVD записи без списка оценок (`scores_at` пуст) получаются заново окнами по дате публикации (до 2000 записей на запрос, не более 40 запросов за запуск) и заменяют прежние по ключу записи — дублей нет; повторный запуск запросов за оценками не делает. Записи, которых NVD уже не отдаёт, помечаются проверенными.

**Надёжность.** Полные выгрузки (KEV, БДУ) записываются в новое «поколение» и становятся действующими только после проверки целостности: файл не пуст и записей не меньше половины прежнего числа (при ≥100 записей). Прежнее поколение хранится для отката («Вернуть предыдущую копию»), более старые удаляются — диск не растёт. Инкрементальные источники обновляют только изменившиеся записи (сравнение по дате изменения). При любой ошибке остаётся последняя корректная копия, поиск и проверки продолжают работать; без интернета приложение работает на локальной базе.

**Решения по сопоставлению.** В той же вкладке — таблица решений: «считать продукт X из базы уязвимостей продуктом каталога Y» либо «исключить как ложное совпадение». Решения общие для всех источников KSC, сохраняются при обновлении базы и приложения; находки пересчитываются сразу.

## Для специалиста ИБ

1. **Поиск** (раздел «База уязвимостей»): по CVE, идентификатору БДУ/OSV, названию и производителю программы, версии, тексту описания. Фильтры: опасность, подтверждённая эксплуатация (KEV), наличие исправления, источник, даты публикации и изменения, «затрагивает нашу инфраструктуру». По умолчанию сверху эксплуатируемые и самые опасные.
2. **Карточка** — общая для всех источников: описание, оценки, даты, ссылки; данные каждого источника отдельно (затронутые продукты и диапазоны); если источники расходятся (опасность, оценка, исправление) — различия показаны с указанием источника; сопоставление с установленным ПО выбранного источника KSC.
3. **«Проверить инфраструктуру»** — быстрый отчёт `quick_extvulns`: уникальные компьютеры, затронутые установки, число уязвимостей, компьютеры с подтверждённой эксплуатацией, по каждой строке — статус сопоставления и его основание, программа и версия, компьютер, IP, ОС, группа KSC, последнее подключение, «в сети сейчас». Можно выбрать несколько CVE или выбрать **программу** (в «Программах» — карточка продукта, «Известные уязвимости») и получить все её известные уязвимости. По умолчанию — устройства, связывавшиеся с KSC за 30 суток; отдельно — «только в сети сейчас». Выгрузка — Excel, HTML, CSV.
4. **«Затрагивают нашу инфраструктуру»** — находки: уязвимости, для которых в каталоге выбранного источника есть подходящее ПО (оценка по каталогу, без запросов к KSC). Новые (не просмотренные) показаны отдельно и в меню красной отметкой — новые серьёзные (критические, высокие или эксплуатируемые). Давние уязвимости (изменены более 90 суток назад) при первой оценке считаются исходным состоянием, а не новостью. Подготовлено для уведомлений: достаточно подписаться на таблицу `vdb_findings` (почта и другие каналы — следующий шаг).
5. **Программы** — столбец «Уязвимости» (число известных для установленных версий, отметка KEV); карточка компьютера — вкладка «Внешние базы».

## Статусы сопоставления

| Статус | Когда |
|---|---|
| Подтверждено источником | продукт сопоставлен надёжно (встроенное соответствие CPE, решение администратора или совпадение названия **и** производителя), и источник явно указывает диапазон или версию, в которую входит установленная |
| Потенциально затронуто | версия входит в диапазон, но продукт сопоставлен только по названию |
| Требуется уточнение | источник не указывает версии (KEV); уязвимость зависит от среды или редакции (конфигурация «И», плагин другого продукта, обновление/редакция CPE); версию нельзя сравнить (например, `8u401` и `8.0.391`); пакет Linux по данным upstream — исправление могло быть перенесено в версию дистрибутива |
| Исправлено | OSV для пакета дистрибутива указывает версию с исправлением, и установленная не ниже; исправление другого выпуска дистрибутива (по метке `~debNNu`) не учитывается |
| Данных недостаточно | у установленной записи нет пригодной версии |

Совпадение по названию программы **никогда** не даёт «подтверждено». CISA KEV только отмечает эксплуатацию и не расширяет круг версий, если другой источник уже указал границы. Сравнение версий — алгоритмами каталога (числовой для Windows, dpkg для Linux): 8.9 < 8.10.

## Устройство (для разработчиков)

```
sources (nvd,kev,osv,bdu: каналы с переключением) → fetch (httpx, повторы, TLS+CA, потоковое скачивание) → stream (JSON-массив/SHA-256 потоком) → parsers (формат → Rec)
   → store (поколения, upsert, VdbVuln — сводка) → sync (расписание, воркер) → match (CatProd ↔ Aff, статусы)
   → analyze (VdbFinding по каталогу) / quick_ext (компьютеры из реестра ПО KSC) → отчёты XLSX/HTML/CSV
```

* Таблицы (миграции `0005_vuln_db`, `0006_cvss_scores`, `0007_vdb_channels`): `vdb_sources`, `vdb_runs`, `vdb_records` (запись источника, `UNIQUE(source, generation, ext_id)`), `vdb_affected` (производитель/продукт/CPE/PURL/версии), `vdb_vulns` (сводка для поиска), `vdb_mappings`, `vdb_findings`.
* `app/vdb/normalize.py` — ключи, CPE 2.3, PURL, CVSS 3 (для OSV только с вектором); `parsers.py` — NVD API 2.0, KEV, OSV, БДУ XML (потоковый разбор); `match.py` — соответствие продукту каталога (решения администратора → таблица `aliases.py` → общее правило по словам названия и производителю), оценка версий, статусы; `sync.py` — планировщик и анализ; `quick_ext.py` — отчёт.
* Общий ключ уязвимости `vuln_key` — CVE, если есть, иначе идентификатор источника; псевдонимы (`aliases`, `upstream`, CVE из БДУ) собираются в `vdb_vulns.ids_text`, карточка открывается по любому.
* **Каналы:** `sources.run_channels(ctx, [(ключ, название, функция)…])` пробует каналы по очереди, отбрасывает недозагруженное поколение и пишет попытки в `ctx.attempts` (→ `vdb_sources.diag`, `vdb_runs.attempts`). `fetch.Http.download` — потоковое скачивание с проверкой места и полноты; `stream.iter_array` — элементы большого JSON по одному; сертификаты Минцифры — `app/vdb/ca/` (`fetch.builtin_ca`).
* **Новый источник:** функция `run_<имя>(ctx)` на основе `run_channels` и запись в `SOURCES`/`INFO` (`vdb/sources.py`), строка в `vdb_sources` (`store.DEFAULTS` и миграция), разборщик в `parsers.py`, тест с образцом данных в `tests/fixtures/vdb`. Остальное приложение не меняется.
* Запросы к KSC — только чтение: реестр ПО читается по записям реестра подходящих версий каталога (`audit.build_source` с `product_ids`), с общими ограничениями (семафор источника, `max_rows`, фоновый отчёт).
* Тесты: `tests/test_vdb_sources.py` (потоковый JSON на границах блоков и память, ленты NVD и контрольные суммы, переключение каналов, оборванные и повреждённые файлы, архивы и изменения OSV, БДУ: 304 и повреждённый файл, место на диске, офлайн, поиск по версии), `tests/test_vdb.py` (разбор реальных образцов NVD/KEV/OSV, синтетический БДУ, сопоставление: ложные совпадения, backport, старые ветки, противоречия, замена данных, синхронизация через подставной HTTP, API), `tests/test_vdb_live.py` (проверка инфраструктуры на синтетическом KSC).

## Источники: форматы, условия, что не подтверждено

* **NVD API 2.0** (`services.nvd.nist.gov/rest/json/cves/2.0`) — проверено на реальных ответах; данные открыты; лимиты и ключ API — по правилам NVD.
* **CISA KEV** (JSON-каталог) — проверено на реальном файле; публикуется открыто.
* **OSV** (`api.osv.dev`: `/v1/vulns/{id}`, `/v1/querybatch`) — проверено на реальных ответах (поле `upstream` у записей Debian); данные — CC-BY 4.0 и лицензии исходных баз.
* **БДУ ФСТЭК** — разбор XML написан по описанию формата (элементы `vul`, `identifier`, `name`, `description`, `vulnerable_software`, `cvss`, `severity`, `solution`, `fix_status`, `identifiers`…) и проверен на синтетическом образце; **на реальной выгрузке не проверялся**: с сервера разработки сайт bdu.fstec.ru недоступен (TLS с корневым сертификатом российского УЦ), публичный REST API не найден. Версии в БДУ — свободный текст; не разобранные (`version_text`) дают статус «требуется уточнение». Условия использования данных нужно прочитать на bdu.fstec.ru: приложение хранит ссылку на первоисточник и не распространяет данные.
* **ScanOVAL ФСТЭК** — отдельный бесплатный сканер для Windows на OVAL-описаниях из БДУ (по публичным обзорам); результаты — отдельные отчёты сканера, официальной документации по формату результатов и тексту лицензии найти не удалось. Использовать его для уточнения нужно через проверки OVAL (реестр, файлы, обновления Windows), которых в реестре установленного ПО KSC нет; интеграция в 0.4.0 не реализована, возможна отдельным этапом после чтения лицензии и документации.
