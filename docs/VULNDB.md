# База уязвимостей

Модуль «База уязвимостей» (0.4.0) собирает сведения об уязвимостях из независимых внешних баз, хранит их локально и проверяет, затрагивают ли они ПО, установленное в подключённых KSC. Результат — **потенциальные** уязвимости; уязвимости, подтверждённые самим KSC (`vapm`), остаются в разделе «Уязвимости» и никогда не смешиваются с ними.

## Для администратора

**Администрирование → База уязвимостей.** Для каждого источника: включение, расписание (каждый час … раз в неделю), параметры, «Обновить сейчас», состояние (дата последней успешной загрузки, число записей, длительность, ошибка) и история загрузок.

| Источник | Что берём | Режим | Особенности |
|---|---|---|---|
| CISA KEV | каталог уязвимостей с подтверждённой эксплуатацией | полная выгрузка (JSON), замена после проверки | включён по умолчанию; даёт производителя и продукт без версий |
| NVD (NIST) | CVE, оценки CVSS, конфигурации CPE с диапазонами версий, ссылки | только изменившиеся записи (по дате изменения, окна по 119 суток) | первая загрузка — за `history_days` (по умолчанию 365), дальше инкрементально; без ключа API 5 запросов за 30 с, с ключом 50; эксплуатируемые CVE, которых нет в загруженном окне, догружаются по одной; отсутствующие оценки CVSS — см. «Оценка опасности» |
| OSV | пакеты и исправления дистрибутивов (Debian и др.) | по изменениям: уточнение по CVE и проверка пакетов Linux из каталога | учитывает исправления, перенесённые дистрибутивом; экосистемы выбирает администратор |
| БДУ ФСТЭК | XML-выгрузка уязвимостей | полная выгрузка, замена после проверки | можно скачать по адресу или загрузить файл вручную (XML или ZIP); сертификат сайта — от российского УЦ: добавьте корневой сертификат в «LDAPS → Сертификаты CA» |

## Оценка опасности (CVSS)

Каждая запись источника хранит **все** оценки CVSS (таблица `vdb_records`, столбец `scores`): версия методики (4.0, 3.1, 3.0, 2.0), балл 0.0–10.0, вектор, уровень, кто выставил, источник, дата обновления записи. Откуда берутся оценки:

| Источник | Что содержит |
|---|---|
| NVD | все оценки `cvssMetricV40/V31/V30/V2`: оценка аналитиков NVD (`primary`) и оценки поставщиков (CNA, `secondary`) |
| БДУ ФСТЭК | CVSS 3.0 (`cvss3`) и CVSS 2.0 (`cvss`) из карточки |
| OSV | только вектор: для CVSS 3.x балл вычисляется по вектору по спецификации FIRST (помечено «вычислена по вектору»); для 4.0 и 2.0 вычисление не поддерживается — оценки нет |
| CISA KEV | оценок нет |

**Основная оценка** (порядок выбора, один на все разделы; остальные оценки остаются и показываются в карточке):

1. CVSS 3.x и 4.0 важнее 2.0 (2.0 — только если других нет).
2. Оценка аналитиков NVD или БДУ (`primary`) важнее оценки поставщика (CNA) и вычисленной по вектору. Иначе оценки CVSS 4.0 от поставщиков вытесняли бы оценку NVD по 3.1.
3. Из равных — более новая методика: 4.0, затем 3.1, затем 3.0.
4. Затем источник: NVD, БДУ, OSV; затем больший балл.

**Уровни** (CVSS 3.x и 4.0): None — 0.0, Low (низкая) — 0.1–3.9, Medium (средняя) — 4.0–6.9, High (высокая) — 7.0–8.9, Critical (критическая) — 9.0–10.0. У CVSS 2.0 уровней None и Critical нет (High — от 7.0). Уровень всегда выводится из балла основной оценки и её методики.

**Нет данных.** Если достоверной оценки нет (NVD ещё не проанализировал запись, источник не дал балл), в таблице и карточке показано «Нет данных». Ноль не подставляется, оценка по названию CVE не вычисляется; недостоверные значения (не число, вне 0–10, неизвестная методика) отбрасываются. Если числовой оценки нет, но источник назвал уровень (например, БДУ — «высокий»), он показан со звёздочкой «по данным источника» и не попадает в фильтр по баллам. Оценка 0.0 — это уровень None, а не отсутствие оценки.

**Таблица и фильтры.** Столбцы «CVSS» (балл и версия методики) и «Критичность». Сортировка по баллу — щелчок по заголовку «CVSS» (сначала самые опасные; без оценки — всегда в конце). Фильтр «CVSS»: готовые диапазоны (критическая 9.0–10.0, высокая 7.0–8.9, средняя 4.0–6.9, низкая 0.1–3.9, нет данных) и свои границы «от/до» (включительно). В API: `score_min`, `score_max`, `no_score`, `sort=score` для `/api/v1/vdb/vulns` и `/api/v1/vdb/findings`.

**Карточка.** Балл, уровень, версия методики, источник оценки и кто её выставил, вектор, дата обновления, ссылка на первоисточник (страница в NVD, БДУ или OSV), список остальных оценок.

**Прежние записи.** Миграция `0006_cvss_scores` добавляет столбцы. При первом запуске воркер один раз преобразует прежние баллы в список оценок (версия определяется по вектору; если определить нельзя — оценка считается недостоверной и не показывается). Потом при ближайшей загрузке NVD записи без списка оценок (`scores_at` пуст) получаются заново окнами по дате публикации (до 2000 записей на запрос, не более 40 запросов за запуск) и заменяют прежние по ключу записи — дублей нет; повторный запуск запросов за оценками не делает. Записи, которых NVD уже не отдаёт, помечаются проверенными.

**Надёжность.** Полные выгрузки (KEV, БДУ) записываются в новое «поколение» и становятся действующими только после проверки целостности: файл не пуст и записей не меньше половины прежнего числа (при ≥100 записей). Прежнее поколение хранится для отката («Вернуть предыдущую копию»), более старые удаляются — диск не растёт. Инкрементальные источники обновляют только изменившиеся записи (сравнение по дате изменения). При любой ошибке остаётся последняя корректная копия, поиск и проверки продолжают работать; без интернета приложение работает на локальной базе.

**Решения по сопоставлению.** В той же вкладке — таблица решений: «считать продукт X из базы уязвимостей продуктом каталога Y» либо «исключить как ложное совпадение». Решения общие для всех источников KSC, сохраняются при обновлении базы и приложения; находки пересчитываются сразу.

## Для специалиста ИБ

1. **Поиск** (раздел «База уязвимостей»): по CVE, идентификатору БДУ/OSV, названию и производителю программы, версии, тексту описания. Фильтры: опасность, подтверждённая эксплуатация (KEV), наличие исправления, источник, даты публикации и изменения, «затрагивает нашу инфраструктуру». По умолчанию сверху эксплуатируемые и самые опасные.
2. **Карточка** — общая для всех источников: описание, оценки, даты, ссылки; данные каждого источника отдельно (затронутые продукты и диапазоны); если источники расходятся (опасность, оценка, исправление) — различия показаны с указанием источника; сопоставление с установленным ПО выбранного источника KSC.
3. **«Проверить инфраструктуру»** — быстрый отчёт `quick_extvulns`: уникальные компьютеры, затронутые установки, число уязвимостей, компьютеры с подтверждённой эксплуатацией, по каждой строке — статус сопоставления и его основание, программа и версия, компьютер, IP, ОС, группа KSC, последнее подключение, «в сети сейчас». Можно выбрать несколько CVE или выбрать **программу** (в «Программах» — карточка продукта, «Известные уязвимости») и получить все её известные уязвимости. По умолчанию — устройства, связывавшиеся с KSC за 30 суток; отдельно — «только в сети сейчас». Выгрузка — Excel, HTML, CSV.
4. **«Затрагивают нашу инфраструктуру»** — находки: уязвимости, для которых в каталоге выбранного источника есть подходящее ПО (оценка по каталогу, без запросов к KSC). Новые (не просмотренные) показаны отдельно и в меню красной отметкой — новые серьёзные (критические, высокие или эксплуатируемые). Давние уязвимости (изменены более 90 суток назад) при первой оценке считаются исходным состоянием, а не новостью. Подготовлено для уведомлений: достаточно подписаться на таблицу `vdb_findings` (почта и другие каналы — следующий шаг).
5. **Программы** — столбец «Уязвимости» (число известных для установленных версий, отметка KEV); карточка компьютера — вкладка «Внешние базы».

## Статусы сопоставления

| Статус | Когда |
|---|---|
| Подтверждено источником | продукт сопоставлен надёжно (встроенное соответствие CPE, решение администратора или совпадение названия **и** производителя), и источник явно указывает диапазон или версию, в которую входит установленная |
| Потенциально затронуто | версия входит в диапазон, но продукт сопоставлен только по названию |
| Требуется уточнение | источник не указывает версии (KEV); уязвимость зависит от среды или редакции (конфигурация «И», плагин другого продукта, обновление/редакция CPE); версию нельзя сравнить (например, `8u401` и `8.0.391`); пакет Linux по данным upstream — исправление могло быть перенесено в версию дистрибутива |
| Исправлено | OSV для пакета дистрибутива указывает версию с исправлением, и установленная не ниже; исправление другого выпуска дистрибутива (по метке `~debNNu`) не учитывается |
| Данных недостаточно | у установленной записи нет пригодной версии |

Совпадение по названию программы **никогда** не даёт «подтверждено». CISA KEV только отмечает эксплуатацию и не расширяет круг версий, если другой источник уже указал границы. Сравнение версий — алгоритмами каталога (числовой для Windows, dpkg для Linux): 8.9 < 8.10.

## Устройство (для разработчиков)

```
sources (nvd,kev,osv,bdu) → fetch (httpx, повторы, TLS+CA) → parsers (формат → Rec)
   → store (поколения, upsert, VdbVuln — сводка) → sync (расписание, воркер) → match (CatProd ↔ Aff, статусы)
   → analyze (VdbFinding по каталогу) / quick_ext (компьютеры из реестра ПО KSC) → отчёты XLSX/HTML/CSV
```

* Таблицы (миграции `0005_vuln_db`, `0006_cvss_scores`): `vdb_sources`, `vdb_runs`, `vdb_records` (запись источника, `UNIQUE(source, generation, ext_id)`), `vdb_affected` (производитель/продукт/CPE/PURL/версии), `vdb_vulns` (сводка для поиска), `vdb_mappings`, `vdb_findings`.
* `app/vdb/normalize.py` — ключи, CPE 2.3, PURL, CVSS 3 (для OSV только с вектором); `parsers.py` — NVD API 2.0, KEV, OSV, БДУ XML (потоковый разбор); `match.py` — соответствие продукту каталога (решения администратора → таблица `aliases.py` → общее правило по словам названия и производителю), оценка версий, статусы; `sync.py` — планировщик и анализ; `quick_ext.py` — отчёт.
* Общий ключ уязвимости `vuln_key` — CVE, если есть, иначе идентификатор источника; псевдонимы (`aliases`, `upstream`, CVE из БДУ) собираются в `vdb_vulns.ids_text`, карточка открывается по любому.
* **Новый источник:** функция `run_<имя>(ctx)` и запись в `SOURCES`/`INFO` (`vdb/sources.py`), строка в `vdb_sources` (`store.DEFAULTS` и миграция), разборщик в `parsers.py`, тест с образцом данных в `tests/fixtures/vdb`. Остальное приложение не меняется.
* Запросы к KSC — только чтение: реестр ПО читается по записям реестра подходящих версий каталога (`audit.build_source` с `product_ids`), с общими ограничениями (семафор источника, `max_rows`, фоновый отчёт).
* Тесты: `tests/test_vdb.py` (разбор реальных образцов NVD/KEV/OSV, синтетический БДУ, сопоставление: ложные совпадения, backport, старые ветки, противоречия, замена данных, синхронизация через подставной HTTP, API), `tests/test_vdb_live.py` (проверка инфраструктуры на синтетическом KSC).

## Источники: форматы, условия, что не подтверждено

* **NVD API 2.0** (`services.nvd.nist.gov/rest/json/cves/2.0`) — проверено на реальных ответах; данные открыты; лимиты и ключ API — по правилам NVD.
* **CISA KEV** (JSON-каталог) — проверено на реальном файле; публикуется открыто.
* **OSV** (`api.osv.dev`: `/v1/vulns/{id}`, `/v1/querybatch`) — проверено на реальных ответах (поле `upstream` у записей Debian); данные — CC-BY 4.0 и лицензии исходных баз.
* **БДУ ФСТЭК** — разбор XML написан по описанию формата (элементы `vul`, `identifier`, `name`, `description`, `vulnerable_software`, `cvss`, `severity`, `solution`, `fix_status`, `identifiers`…) и проверен на синтетическом образце; **на реальной выгрузке не проверялся**: с сервера разработки сайт bdu.fstec.ru недоступен (TLS с корневым сертификатом российского УЦ), публичный REST API не найден. Версии в БДУ — свободный текст; не разобранные (`version_text`) дают статус «требуется уточнение». Условия использования данных нужно прочитать на bdu.fstec.ru: приложение хранит ссылку на первоисточник и не распространяет данные.
* **ScanOVAL ФСТЭК** — отдельный бесплатный сканер для Windows на OVAL-описаниях из БДУ (по публичным обзорам); результаты — отдельные отчёты сканера, официальной документации по формату результатов и тексту лицензии найти не удалось. Использовать его для уточнения нужно через проверки OVAL (реестр, файлы, обновления Windows), которых в реестре установленного ПО KSC нет; интеграция в 0.4.0 не реализована, возможна отдельным этапом после чтения лицензии и документации.
