# Подготовка выпуска

Обязательные шаги перед `scripts/release.sh patch|minor`:

1. **Тесты и сборка**: `cd backend && .venv/bin/python -m pytest -q`, `cd frontend && npm run build`, `python3 scripts/check_private_data.py`. CI на GitHub должен быть зелёным.
2. **Компоненты и зависимости** (раздел «Администрирование → Компоненты» показывает доступные версии, проверка идёт в фоне):
   * для каждого компонента из `backend/app/components.json` решите: обновить, отложить или признать несовместимым;
   * совместимая стабильная версия, прошедшая тесты, — обновляется (`requirements.txt`, `package.json`, Dockerfile, поле `verified` реестра);
   * отложенное обновление фиксируется в `decision` с причиной (несовместимое API, регрессия, проблема безопасности, не пройдены тесты, нужна миграция, выпуск не признан стабильным);
   * ссылки `release_notes` — на конкретные официальные страницы выпусков (GitHub Releases, npm, PyPI, сайт разработчика) без трекинговых параметров;
   * после рассмотрения поставьте `reviewed_for` = номер выпуска и дату в `reviewed_at`. Без этого `release.sh` не создаст выпуск.
   * CI проверяет, что каждая зависимость из `requirements.txt` и `package.json` есть в реестре, а закреплённые в Dockerfile версии Nuclei и шаблонов совпадают с реестром.
   * Рабочие установки версии не обновляют сами: приложение — только проверенным выпуском, сигнатуры и разрешённые шаблоны — по существующей модели проверки и утверждения.
3. **CHANGELOG.md**: раздел `[Unreleased]` описывает исправления, новые возможности, обновлённые компоненты (с ссылками на официальные Release Notes важных зависимостей), миграции базы, особенности обновления, известные ограничения и проверенные сценарии. Текст на русском, без внутренних адресов, имён серверов, учётных записей и секретов.
4. **Скриншоты** для значительных изменений интерфейса — только с вымышленными данными (`example.local`, 192.0.2.0/24).
5. `scripts/release.sh patch|minor`, затем `git push origin master v<версия>`; релиз и образы GHCR публикует CI. Рабочую установку не обновлять автоматически.
