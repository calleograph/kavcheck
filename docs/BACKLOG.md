# Отложенные задачи (после 0.9.3)

Принятые к выполнению в следующих версиях, без изменения приоритета «стабильность на больших реальных базах».

1. **«Состояние защиты» и «Уязвимости KSC» на больших источниках.** Сейчас обе страницы читают KSC напрямую и держат результат в памяти backend (100 тыс. устройств — холодный запрос ≈15 с и ≈180 МБ на источник; 400 тыс. не помещаются в 1 ГБ backend). Перенести на подготовленные данные (как зоны, EOL и устройства): расчёт в worker порциями, страницы читают агрегаты SQL; до этого — ограничение размера кэша и отказ с понятным сообщением вместо исчерпания памяти.
2. **Унификация компактных таблиц.** Правило «до трёх значений и +N, полный список по раскрытию, серверная пагинация» применено в карточке компьютера, плане устранения и (с 0.9.0) в части таблиц; остальные таблицы приложения с множеством связанных записей перевести на то же правило. Выгрузки и счётчики не сокращаются.
3. **Фильтр по департаменту (зоне) для находок каталога** в «Базе уязвимостей»: находки считаются по каталогу источника, а не по компьютерам; нужен расчёт по подготовленным данным зон.
4. **Повторное использование результата отчёта** по неизменившимся данным (отпечаток данных KSC и параметров; не выдавать устаревший результат за актуальный).
5. **Проверка на реальных источниках** — [VERIFY_REAL_SOURCES.md](VERIFY_REAL_SOURCES.md); по её итогам — замеры реального масштаба (время, пик памяти worker и PostgreSQL, планы запросов) в PERFORMANCE.md.
6. **Сквозные отчёты — доработка после 0.10.0.** Единые `FilterBar`, боковая панель и конструктор (подробность, столбцы, шаблоны) введены в 0.10.0 на страницах компьютеров, программ, каталога, уязвимостей KSC, базы уязвимостей, EOL, устройств и пользователей, состояния защиты, событий, зон и карточек. Осталось: отчёт по уязвимостям внешних баз без выбора строк (сейчас — не больше 300 уязвимостей на отчёт), боковая панель устройств для уязвимостей внешних баз и для зон (в обзоре зон числа ведут на страницу зоны), шаблоны для отчётов проверки версий и зон, повторное использование результата отчёта (п. 4).
7. **Pentest и главная — доработка после 0.11.0.** (В 0.12: Nuclei, NSE, точность CVE, отчёты; остаётся ниже.) Не сделано: UDP-сканирование; authenticated scan (учётные данные) для OVAL — сейчас только пакеты устройства KSC, связанного вручную; автоматическая проверка OVAL для всех находок задания (сейчас по кнопке в находке); расписание повторных сканирований; раскрывающиеся строки в остальных таблицах (каталог, события, база уязвимостей, зоны); перенос главной на подготовленные данные для очень больших источников (сейчас записи защиты читаются через кэш страницы «Состояние защиты»); проверка чтения лицензий на реальной KSC.
8. **Pentest после 0.12.** Не сделано или не проверено: проверка на настоящем 1С-Битрикс (в стенде только синтетическая страница с признаками платформы); данные бюллетеней Ubuntu, Red Hat и других дистрибутивов (сейчас исправления пакетов проверяются для Debian по OSV; для остальных — «требует проверки»); перевод описаний CVE (оригинал сохраняется, русские пояснения строятся из структурированных данных); повторный анализ старых результатов по новым правилам (с явной пометкой); уровни критичности отчёта в остальных разделах (компонент `SeverityLevels` общий, подключён к Pentest; прочие отчёты пока используют прежний выбор одного уровня); частичный запуск Nuclei по индивидуальным категориям на сетевых службах без `port` в шаблоне; проверки через авторизованный доступ; UDP.


## CVE Hunt (0.14): что не сделано

* Повторное использование прежних сетевых замеров (Pentest, предыдущие CVE Hunt) с показом возраста и режимом принудительной перепроверки: сейчас сетевой замер выполняется всегда, возраст показан только у данных KSC.
* Предварительная оценка инфраструктуры по сохранённым сведениям без сети при появлении новой CVE.
* Выбор строк в результатах и отчёт «только по выбранным»; сохранённые сценарии («Поиск устаревших PHP»); приоритет проверки активных серверов.
* Проверка реального PHP/Битрикс за обратным прокси; backport-исправления не-Debian дистрибутивов — «Требует проверки».

## BI-выгрузки и владельцы устройств (после 0.15.0)

* Ручное объединение двух устройств BI (переименование без устойчивого идентификатора сейчас выглядит как новое устройство) и ручные корректировки владельца как отдельный источник сведений с журналом.
* Устойчивый идентификатор, общий с KSC (например, GUID агента в выгрузке), для автоматического «надёжного» сопоставления; сейчас «надёжное» — только решение администратора.
* Объединение истории пользователей KSC (наблюдения за вошедшими) со шкалой владельцев BI в одной ленте; сейчас они показаны рядом, но отдельно.
* Другие типы источников (CSV, выгрузка по HTTPS, каталог LDAP как источник подразделений) — функция получения файла в `bi/service.py`.
* Ускорение разбора больших XLSX (≈ 35 с на 50 тыс. строк в тестовом файле со строками inline): собственный потоковый разбор листа вместо openpyxl.
* Проверка на настоящей выгрузке организации (предоставленный пример `20261029_115045.xlsx` на сервер разработки не передан — проверено на синтетическом файле той же структуры).
