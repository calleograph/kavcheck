# Отложенные задачи (после 0.9.3)

Принятые к выполнению в следующих версиях, без изменения приоритета «стабильность на больших реальных базах».

1. **«Состояние защиты» и «Уязвимости KSC» на больших источниках.** Сейчас обе страницы читают KSC напрямую и держат результат в памяти backend (100 тыс. устройств — холодный запрос ≈15 с и ≈180 МБ на источник; 400 тыс. не помещаются в 1 ГБ backend). Перенести на подготовленные данные (как зоны, EOL и устройства): расчёт в worker порциями, страницы читают агрегаты SQL; до этого — ограничение размера кэша и отказ с понятным сообщением вместо исчерпания памяти.
2. **Унификация компактных таблиц.** Правило «до трёх значений и +N, полный список по раскрытию, серверная пагинация» применено в карточке компьютера, плане устранения и (с 0.9.0) в части таблиц; остальные таблицы приложения с множеством связанных записей перевести на то же правило. Выгрузки и счётчики не сокращаются.
3. **Фильтр по департаменту (зоне) для находок каталога** в «Базе уязвимостей»: находки считаются по каталогу источника, а не по компьютерам; нужен расчёт по подготовленным данным зон.
4. **Повторное использование результата отчёта** по неизменившимся данным (отпечаток данных KSC и параметров; не выдавать устаревший результат за актуальный).
5. **Проверка на реальных источниках** — [VERIFY_REAL_SOURCES.md](VERIFY_REAL_SOURCES.md); по её итогам — замеры реального масштаба (время, пик памяти worker и PostgreSQL, планы запросов) в PERFORMANCE.md.
