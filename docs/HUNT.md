# CVE Hunt — целевой поиск уязвимостей и программ

Раздел отвечает на вопрос «какие компьютеры затронуты конкретной CVE или продуктом?». Это не полный Pentest: проверяется только выбранное. Работает на тех же механизмах, что и Pentest: сканер и его очередь (`pt_jobs`, профиль `hunt`), движки Nmap/NSE/Nuclei, база уязвимостей, каталог программ KSC, зоны, отчёты. Второй базы уязвимостей, второго генератора отчётов и своей очереди нет.

## Как это работает

1. **Критерии** (`app/hunt/criteria.py`): CVE (диапазоны уязвимых версий, платформа и условия берутся из `vdb_affected`, подходящая безопасная проверка — разрешённый шаблон Nuclei) и/или продукты из каталога программ (версия: любая / конкретные / диапазон / ниже / выше; «только версии с известными уязвимостями» и «только с завершённой поддержкой» — по базе уязвимостей и данным EOL). Логика «любой из критериев» (по умолчанию) или «все».
2. **Порты** (`hunt/kb.py`, `criteria.suggest_ports`): обычные порты продукта + порты, где такой сервис находили прежние сканирования; оператор добавляет свои. Проверяются только они (`nmap -p …`), профиль «топ-1000» и полный Pentest не используются. Для продуктов, которые могут не раскрывать версию (PHP за nginx/Apache), мастер прямо предупреждает о неполном охвате.
3. **Область** (`hunt/scope.py`): источники KSC (активные компьютеры из подготовленных данных зон), зоны, группы, свои адреса/сети/диапазоны, «вся инфраструктура» (сети администратора `pentest.hunt_networks` + KSC); исключения. Все адреса проходят область разрешений Pentest (`pentest/targets.py`) при создании и перед сетевыми действиями; сторонние адреса запускать нельзя.
4. **Режимы**: «По данным KSC» (без сети; реестр программ KSC читается тем же кодом, что раздел «Программы»), «Сетевая проверка», «Комбинированный» (основной): данные KSC и сеть объединяются по IP, различия версий отмечаются.
5. **Сканер** (`pentest/scanner.py`): этапы портов и сервисов (`-sV`), затем только нужные безопасные проверки — NSE `http-headers` для веб-продуктов и шаблоны Nuclei, привязанные к выбранным CVE (`nuclei.plan_only`: без категорий и без обнаружения технологий). Сопоставление (`hunt/match.py`): CVE оценивает тот же анализ применимости, что и в Pentest (роль компонента, платформа, исправления дистрибутива Debian), результат фильтруется по выбранной CVE — посторонние CVE не попадают. Продукт определяется по CPE/названию Nmap либо признаку в ответе (`X-Powered-By: PHP/8.1.12`).
6. **Результаты** (`hunt_hits`): статусы «Подтверждено» (проверка подтвердила), «Вероятно» (продукт и версия в уязвимом диапазоне), «Требует проверки» (нет версии, пакет дистрибутива, зависимость от конфигурации), «Не удалось проверить» (адрес недоступен или проверка не завершена). «Не обнаружено» не хранится — охват виден по адресам задания. Отсутствие сетевого признака не означает отсутствия продукта.
7. **Связь с KSC** (`hunt/enrich.py`): имя, ОС, группа, источник, последняя связь, зона ответственности, пользователь. Устройства разных источников не склеиваются по имени или IP: адрес, найденный у нескольких устройств, помечается «неоднозначно». Пользователь — последнее наблюдение KAV Checker в списках KSC (не владелец и не интерактивный сеанс); неизвестный — «Не определён», зона — «Не назначена»; компьютер вне KSC сохраняется с IP.

## Отчёт «Результаты целевого поиска уязвимостей» (`quick_hunt`)

Компактная таблица: имя компьютера (первый столбец), пользователь/владелец, зона, IP, продукт, версия, результат, основание (+ критерий, порт, ОС, источник данных, возраст данных). По умолчанию — «Подтверждено» и «Вероятно»; «Требует проверки» и журнал охвата (все проверенные адреса) включаются отдельно. HTML — самостоятельный файл (встроенные стили и скрипт, поиск, сортировка, фильтры по результату, печать), PDF, XLSX (автофильтр, ширины), CSV (UTF-8 BOM). Описаний CVE, CVSS и ссылок в отчёте нет; обязательное примечание: отсутствие совпадения при сетевом сканировании не доказывает отсутствие ПО.

## История и повтор

Задание хранит критерии, область, порты, режим, версии движков, результаты, журнал выполнения (`/pentest/jobs/{id}/log`) и отчёты. «Повторить проверку» создаёт задание на тех же условиях; сравнение (`GET /hunt/jobs/{id}/compare`): новые, сохранившиеся, больше не соответствующие и «не удалось перепроверить». Недоступный при повторе компьютер не считается исправленным.

## Контекстные действия

«Найти в инфраструктуре» — в карточке CVE (база уязвимостей), на странице программы и в строке EOL: мастер открывается с выбранным критерием, версиями и портами.

## Права и безопасность

Раздел — аналитику и администратору; источники KSC — по правам пользователя; сетевой поиск выполняет только изолированный сканер; произвольные скрипты NSE, шаблоны Nuclei и команды запустить нельзя (только каталог разрешённых проверок; активные проверки администратора здесь не используются). Секреты в доказательствах скрываются.

## Что не реализовано (честно)

Повторное использование прежних сетевых замеров и предварительная оценка «без сети» по сохранённым сведениям при появлении новой CVE; выбор строк и отчёт «только по выбранным»; сохранённые сценарии поиска. Подробнее — docs/BACKLOG.md.
