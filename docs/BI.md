# BI-выгрузки: владельцы устройств и история принадлежности

KAV Checker может регулярно получать корпоративную Excel-выгрузку «сотрудник × устройство» из BI-системы и хранить **историю принадлежности**: устройство → сотрудник → период наблюдения → источник. Так можно найти не только текущего, но и прежних владельцев компьютера, в том числе компьютера с неисправной защитой, у которого в KSC нет пользователя.

Главный принцип: новая выгрузка обновляет текущее представление, но **не уничтожает историю**. Данные BI и KSC объединяются только при достаточных основаниях; происхождение каждого сведения сохраняется.

## Подключение

**Администрирование → Источники данных → BI-системы — Excel через SMB.**

| Настройка | Что задаёт |
|---|---|
| Сервер, порт, общий ресурс, папка | SMB-папка с выгрузкой. Доступ **только на чтение**: файл не изменяется, не удаляется и не переименовывается. |
| Учётная запись | Отдельная учётная запись только для чтения. Пароль хранится зашифрованным (`APP_MASTER_KEY`), через API не возвращается и в журналы не попадает. |
| Требовать шифрование SMB 3.x | Включено по умолчанию. |
| Выбор файла | **Фиксированное имя** (BI перезаписывает один файл, например `computers.xlsx`) или **новейший файл по маске** (`export_*.xlsx`). |
| Время получения и часовой пояс | Раз в сутки; часовой пояс также используется для дат без пояса в самой выгрузке. |
| Проверки и поведение при ошибках | Частичный импорт, допустимая доля отклонённых строк, порог изменения числа записей, повторы после сбоя, ожидание стабильности файла, пределы размера и строк, «выгрузка полная». |
| Хранение исходных файлов | Сколько копий и сколько суток хранить. История импортов и принадлежности хранится отдельно и не удаляется. |

**Разрешённые SMB-серверы** (там же) — имена с маской или сети CIDR. Пусто — любой сервер, кроме петлевых и link-local адресов.

Кнопки источника: **Проверить подключение** (разрешён ли сервер, TCP, вход и диалект SMB, чтение папки, выбор файла, право чтения), **Проверить структуру файла**, **Запустить импорт**, **Загрузить файл…** (импорт файла, переданного администратором), **Посмотреть журнал**, **Настройки хранения**.

### Рекомендуемая публикация файла на стороне BI

Записывать выгрузку во временный файл (`computers.xlsx.tmp`) и затем заменять готовый файл одним переименованием. KAV Checker пропускает временные и блокировочные файлы (`~$…`, `.tmp`, `.part`), а перед копированием проверяет, что размер и время изменения не меняются (`stable_s`) — и до, и после копирования. Изменяющийся файл не читается: получение откладывается.

## Сопоставление столбцов

Выгрузки разных организаций устроены по-разному. При первом подключении администратор загружает образец или выполняет пробное чтение с SMB — KAV Checker показывает листы, столбцы и примеры значений, предлагает сопоставление по названиям и проверяет первые 2000 строк. **В базу при этом ничего не записывается.** Импорт начинается только по явному действию администратора (или по расписанию после сохранения профиля).

Поля внутренней модели: пользователь (ФИО), рабочая почта, подразделение, дата создания учётной записи, имя компьютера, устойчивый идентификатор устройства (серийный или инвентарный номер), ОС, тип собственности, состояние антивируса по BI, сторонний антивирус, дата наблюдения в источнике, дата ручного исправления, начало и окончание владения (если источник их передаёт); флаги происхождения («Из базы …», «Из ручного справочника»). Несопоставленные столбцы сохраняются как дополнительные сведения.

Обязательно: имя компьютера **или** идентификатор устройства, и ФИО **или** почта.

## Проверки при импорте

* Контейнер XLSX проверяется до разбора: число частей, распакованный объём, степень сжатия (защита от архивных бомб). Чтение — потоковое (openpyxl `read_only`), формулы не вычисляются, макросы не выполняются, внешние ссылки не загружаются, XML разбирается через defusedxml.
* Нет обязательного столбца, файл повреждён или не докопирован, строк больше предела, файл старше уже импортированного снимка, слишком сильно изменилось число записей — **импорт отклоняется целиком**, предыдущий снимок остаётся опубликованным, причина видна в журнале и на карточке источника.
* Отдельные некорректные строки (нет имени компьютера, условное имя без сотрудника) — частичный импорт с перечнем отклонённых строк. В таком снимке исчезновение устройств не учитывается.
* Даты из будущего (например, 2037 год) и раньше 1990 года сохраняются как есть, отмечаются и **не используются** как даты наблюдения. Ничего не подменяется текущим временем.
* Повторяющиеся строки, несколько сотрудников за одним устройством, изменение набора столбцов — предупреждения импорта.

## Повторные импорты

* Тот же файл (SHA-256) — «Изменений нет», без обработки.
* Новый файл с тем же содержанием (другое оформление или порядок строк) — «Изменений нет», даты наблюдения продлеваются.
* Записи без изменений не копируются: продлевается версия; изменённая запись — новая версия, прежняя остаётся.

Публикация снимка — одна транзакция под блокировкой источника и арендой задания (`JOBS`, вид `bi`): страницы во время импорта видят прежний снимок.

## История принадлежности

Связь «устройство × сотрудник» (`bi_owners`) хранит даты **выгрузок**, в которых она наблюдалась (первая и последняя), число выгрузок, достоверную дату наблюдения из самой выгрузки, период владения — только если источник его передаёт, достоверность и основание.

| Состояние | Когда |
|---|---|
| Текущий владелец по BI | устройство есть в последнем снимке и указано за сотрудником |
| Прежний владелец | устройство есть в последнем снимке, но за другим сотрудником. Известно лишь, что смена произошла **между двумя выгрузками**; точная дата передачи не выдумывается |
| Историческая связь, текущий статус неизвестен | устройства нет в последнем снимке (при выключенной «выгрузке полной» отсутствие ничего не меняет) |

Прежний владелец не удаляется. Если устройство вернулось с тем же сотрудником, связь продолжается. Дата создания учётной записи и дата ручного исправления — атрибуты, а не дата начала владения.

**Ключи.** Сотрудник — рабочая почта, без неё — ФИО (низкая достоверность). Устройство — устойчивый идентификатор, если сопоставлен (тогда переименование сохраняется в истории и поиске), иначе короткое имя. Условные имена («Личный ПК», имена с пробелами, список настраивается) — отдельное устройство на каждого сотрудника.

Данные разных BI-источников не смешиваются: каждая запись принадлежит одному подключению.

## Сопоставление с KSC

Используются подготовленные данные зон (текущее поколение каждого включённого источника KSC); KSC не опрашивается. Пересчёт — после импорта и при новом расчёте данных зон.

| Уровень | Условие |
|---|---|
| **Надёжное** | подтверждено администратором |
| **Предполагаемое** | имя единственное среди всех источников KSC **и** подтверждено ещё одним признаком: совпадает семейство ОС, полное имя (FQDN) или учётная запись KSC на компьютере совпадает с почтой сотрудника |
| Не сопоставлено: совпадает только имя | других признаков нет |
| Не сопоставлено: несколько компьютеров | имя есть у нескольких компьютеров (в том числе в разных KSC); отклонение одного из них не делает имя «единственным» |
| Не сопоставлено: признаки противоречат | например, BI — Linux, KSC — Windows |

IP-адрес не используется. Условные имена по имени не сопоставляются. Решения администратора (вкладка «Сопоставление BI и KSC»: подтвердить, отклонить, сбросить) сохраняются при пересчёте и пишутся в журнал действий (`bi.match.*`). Отклонённая пара больше не предлагается. Устройство BI без соответствия остаётся в базе и доступно для поиска: «Не найдено соответствие в подключённых источниках KSC» — это **не** вывод об отсутствии Kaspersky.

## Антивирус по BI и состояние KSC

Поля «Использует антивирус» и «Сторонний антивирус» сохраняются и показываются **отдельно** от фактической защиты KSC. Показатели главной и раздела «Состояние защиты» не меняются. Расхождения (BI: антивирус используется — KSC: продукта нет или защита не работает; BI: не используется — KSC: работает; сторонний антивирус при установленном Kaspersky; разная ОС; учётные записи KSC не совпадают с почтой владельца) показываются в карточке и в отчёте «Расхождения BI и KSC».

## Где видно

* **Карточки компьютера** («Устройства и пользователи», «Зоны ответственности», «Компьютеры»): блок **«Владелец и история принадлежности»** — текущий владелец, шкала владельцев (нажатие раскрывает выгрузку-основание), тип устройства, источник и дата снимка, антивирус по BI, расхождения. Если соответствие не подтверждено — объяснение и возможные устройства BI, владелец не показывается.
* **«Состояние защиты»** и панели устройств на главной: владелец под именем компьютера.
* **«Устройства и пользователи»**: вкладки «Устройства», «Пользователи KSC» (по умолчанию только Windows — для Linux KSC обычно не передаёт пользователей, фиктивных записей нет), «Пользователи BI» (сотрудники и устройства; поиск по ФИО, почте, подразделению, текущему и прежнему имени устройства; отбор текущих и прежних владельцев, неопределённых владельцев, расхождений), «Сопоставление BI и KSC».

## Отчёты

Вид **«Владельцы устройств (BI)»** общего конструктора (HTML, PDF, XLSX, CSV), учитывает фильтры страницы: «Устройства и владельцы», «История принадлежности устройств», «Неопределённые владельцы», «Расхождения BI и KSC», «Проблемы защиты и контактные лица». В отчёте указаны происхождение и дата сведений BI.

## Права и персональные данные

| Действие | Роль |
|---|---|
| Настройка BI-источников, загрузка файла, решения по сопоставлению | администратор |
| Списки сотрудников и устройств BI, почта, отчёты BI | аналитик и администратор **с доступом ко всем источникам KSC** (выгрузка не делится по источникам KSC) |
| Блок «Владелец» в карточке компьютера | любой пользователь с доступом к источнику KSC; почта — только аналитику и администратору |

Настройка, проверка подключения, запуск, загрузка и решения по сопоставлению записываются в журнал действий; события импорта — в журнал событий (категория `bi`, без персональных данных, с его сроком хранения). В репозиторий и примеры не попадают реальные выгрузки: тесты используют синтетические данные `example.local`.

## Для разработчиков

* `backend/app/bi/`: `profile.py` (поля, подсказка сопоставления, нормализация строки), `xlsx.py` (проверка контейнера и потоковое чтение), `smb.py` (SMB только чтение, выбор файла, стабильное копирование, диагностика), `importer.py` (разбор в потоке, проверки, публикация одной транзакцией), `match.py` (сопоставление с KSC), `read.py` (карточки, списки, владельцы для списков KSC), `service.py` (worker: расписание, повторы, хранение копий).
* Таблицы (миграция 0021): `bi_sources`, `bi_imports`, `bi_records` (версии записей), `bi_persons`, `bi_devices`, `bi_owners`, `bi_matches`.
* API — `api/bi.py`; отчёт — `reports/quick_bi.py` (вид `quick_bi`); интерфейс — `pages/admin/BiSourcesAdmin.tsx`, `pages/people/*`, `components/OwnerBlock.tsx`.
* Новый тип источника (например, CSV или выгрузка по HTTPS) добавляется функцией получения файла в `service.py`; разбор, история и сопоставление не меняются.
* Тесты: `tests/test_bi_import.py`, `test_bi_match.py`, `test_bi_api.py`; на настоящем SMB — `test_bi_smb_live.py` (`BI_SMB_TEST_HOST`, `BI_SMB_TEST_USER`, `BI_SMB_TEST_PASS`).

## Ограничения

* Надёжное сопоставление с KSC — только решением администратора: в выгрузках обычно нет идентификатора, который хранит и KSC.
* Без устойчивого идентификатора устройства переименование компьютера в BI выглядит как новое устройство.
* Сотрудник без почты определяется по ФИО: однофамильцы с одинаковым ФИО в одном источнике сливаются (достоверность «низкая»).
* Проверка структуры перед импортом смотрит первые 2000 строк; полный файл проверяет импорт.
