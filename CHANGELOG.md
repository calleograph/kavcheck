# Журнал изменений

Для пользователей: что появилось и что изменилось в каждой версии. Версия задаётся файлом VERSION.

## [Unreleased]

### База уязвимостей

- Новый раздел «База уязвимостей»: единый поиск по уязвимостям из независимых источников — NVD (API 2.0), CISA KEV, OSV и БДУ ФСТЭК — и проверка, затрагивают ли они ПО, установленное в подключённых KSC. Поиск по CVE, идентификатору БДУ, названию и производителю программы, версии и тексту; фильтры по опасности, подтверждённой эксплуатации (отдельная заметная отметка «эксплуатируется»), наличию исправления, источнику, датам; по умолчанию сверху эксплуатируемые и самые опасные.
- Карточка уязвимости объединяет источники, сохраняя данные каждого отдельно; расхождения (опасность, оценка, исправление) показаны с указанием источника; кнопка «Проверить инфраструктуру» открывает быстрый отчёт о потенциально затронутых компьютерах (уникальные компьютеры, установки, уязвимости; статус и основание по каждой строке; Excel, HTML, CSV). Можно выбрать несколько CVE или программу — все её известные уязвимости.
- Сопоставление с каталогом установленного ПО: статусы «подтверждено источником», «потенциально затронуто», «требуется уточнение», «исправлено», «данных недостаточно»; совпадение по одному названию подтверждением не считается; для пакетов Linux учитываются исправления дистрибутива (OSV) и переносимые исправления; решения администратора по сопоставлению сохраняются.
- «Затрагивают нашу инфраструктуру»: находки по каталогу источника KSC, новые серьёзные — с отметкой в меню; в «Программах» — число известных уязвимостей, в карточке компьютера — вкладка «Внешние базы».
- Локальная база и обновление: расписание и выбор источников, ручной запуск, загрузка файла БДУ, состояние источников (дата, записи, длительность, ошибки, история); полные выгрузки подменяют данные только после проверки целостности, предыдущая копия хранится для отката; при ошибке остаётся последняя корректная база. Миграция `0005_vuln_db`.
- Подробности, источники, условия, измерения скорости и что не проверено (разбор БДУ на реальной выгрузке, ScanOVAL) — в `docs/VULNDB.md`.

## [0.3.0] — 2026-10-24

### Быстрые контекстные отчёты

- Отчёт из любого раздела за 2–3 действия: отметьте строки флажками (или нажмите «Отчёт по этой уязвимости») → «Сформировать отчёт» → в боковой панели сразу число затронутых компьютеров, условия, замечания о достоверности и первые строки → «Excel», «HTML для руководства» или «CSV». Источник, выбранные записи, поиск, фильтры, давность связи и «только в сети» передаются в отчёт автоматически; дополнительные условия — в раскрывающемся блоке «Дополнительно».
- «Уязвимости»: новая вкладка со списком уязвимостей KSC (KLA, CVE, опасность, программы, число компьютеров, исправление) с поиском по CVE и KLA; отчёт по одной или нескольким уязвимостям. Вкладки «Уязвимые программы» и «Компьютеры» тоже выбирают строки; карточка компьютера уязвимостей и карточка компьютера — «Подробный отчёт».
- «Компьютеры»: отчёт по выбранным устройствам — состояние, защита, установленное ПО, уязвимости (разделы выбираются). «Состояние защиты»: отчёт по текущей категории и фильтрам или по выбранным устройствам. «События безопасности»: отчёт по текущему списку (период, результат, угроза, поиск) или по выбранным событиям. «Каталог программ» и конструктор проверки версий: «Сформировать отчёт» с тем же предпросмотром.
- Правила подсчёта: уникальные компьютеры; уязвимые установки (компьютер × программа); обнаружения KSC (компьютер × уязвимость × программа); распределение по опасности — по наивысшему уровню на компьютер, сумма равна числу компьютеров. Выбор нескольких уязвимостей не удваивает компьютеры.
- «Связывался с KSC за N суток» и «в сети сейчас» — разные условия: по умолчанию учитываются устройства, связывавшиеся за период; «в сети сейчас» — отдельный фильтр, а в результатах всегда есть столбец «В сети сейчас». Если KSC не передаёт флаг присутствия, это отмечено, и фильтр не применяется молча.
- Достоверность: отчёт различает уязвимости, подтверждённые KSC, и результат проверки версий по условию пользователя; записи без привязки уязвимости к установленной версии, скрытые неактивные компьютеры и записи кластеров перечислены в замечаниях.
- Excel: листы «Сводка», основная таблица, «Компьютеры», «Программы», «Уязвимости», «Параметры»; фильтры, сортировка, закреплённый заголовок, подобранная ширина. HTML: самодостаточный документ для руководства (показатели, распределение по опасности, условия, замечания, таблицы), без внешних ресурсов и скриптов, печать и PDF средствами браузера; HTML есть и у проверки версий.
- Предпросмотр строится из того же документа, что и файлы, и кэшируется: числа в просмотре и готовом отчёте совпадают, повторное открытие не читает KSC заново. Файлы формируются фоновым воркером; готовый отчёт открывается в «Отчётах» (просмотр, повтор, скачивание XLSX, CSV, HTML).

- События безопасности: устройства, которых уже нет в KSC, показываются как «Удалённое устройство (ID …, имя неизвестно)», IP-адрес — «нет данных» (в публичном представлении KSC имя на момент события недоступно); в отчёте это отмечено и посчитано. Отчёт по событиям читает журнал одним запросом вместо постраничного чтения с повторным подсчётом: 15 тыс. событий за 30 суток на базе из 300 тыс. событий — 2,4 с вместо 16 с, повторный просмотр из кэша без запросов к SQL Server.
- HTML-отчёт при сокращении выборки (больше 3 000 строк в таблице) явно предупреждает об этом вверху документа и в панели предпросмотра; показатели сводки (компьютеры, установки, обнаружения) всегда посчитаны по полному результату, полный список — в Excel и CSV.
- Список уязвимостей на очень большой базе (650 тыс. обнаружений) загружается за 15 секунд вместо двух минут: группировка только по идентификатору уязвимости, имена и ссылки — отдельным небольшим запросом.

### Обновление с 0.2.2

- Миграций базы нет. Версия 0.3.0 не меняет данные KAV Checker; рабочая схема KSC не затрагивается (только чтение).
- Обновление с 0.1.0 выполняется одним шагом (миграции 0002–0004 применяются подряд); порядок и откат — как в разделе «Обновление с 0.1.0» ниже.

### Исправлено: условия проверки версий

- Отчёт должен точно соответствовать условию пользователя. Условие теперь записывается словами пользователя («Установленная версия ниже 8.4.15») и в таком виде показывается в просмотре, готовом отчёте, XLSX и CSV. Столбец «Требуемая версия» переименован в «Целевая версия» (куда обновить, например «8.4.15 или выше»): раньше его легко было принять за условие проверки. «Не ниже» заменено на «выше или равна».
- Перед выполнением условие сверяется с заданным при создании отчёта: если оператор, граница, исключения или ветки отличаются, отчёт не формируется — понятная ошибка вместо пустого отчёта по другому условию. Поля, не относящиеся к выбранному оператору, отбрасываются при приёме; диапазон с перепутанными границами отклоняется.
- Если условию не соответствует ни одна установка, отчёт объясняет почему: сколько записей реестра найдено и в каком диапазоне версий.
- Просмотр и отчёт используют один и тот же предел строк: число компьютеров в просмотре совпадает с готовым отчётом.
- Сравнение версий: предварительная версия с нулевыми частями (`5.0.0-beta`) считалась старше `5.0`.
- Проверка версий: фильтр «только устройства в сети сейчас» (по флагу KSC «видимо»), отдельный от «связывались за N суток»; в результате показано, сколько компьютеров скрыто.

## [0.2.2] — 2026-10-24

- Вход доменных пользователей по LDAPS — по короткому имени учётной записи (например, `ivan.petrov`), без `@домен` и `ДОМЕН\`: имя ищется во всех настроенных доменах. Если одно имя есть в нескольких доменах, на странице входа выбирается домен; вход в «чужой» домен исключён.
- Раздел «LDAP» переименован в «LDAPS». Проверка подключения к контроллеру домена и проверка входа пользователя разделены: «Проверка входа» проходит тот же путь, что настоящий вход (поиск в каждом домене, пароль, группы, правила, второй фактор), и показывает причину на каждом шаге.
- Точная причина неудачного входа (пользователь не найден, ошибка поиска, пароль отклонён контроллером, нет разрешённой группы) — в журналах администратора; пользователь видит общее сообщение.
- «Состояние защиты»: фильтр «Только онлайн» (включён по умолчанию) — числа проблем, списки и поиск только по устройствам, которые KSC сейчас видит в сети; колонка «Онлайн». «В сети» определяется по флагу KSC «видимо», а не по давности подключения; нет сведений — «нет данных». Статус «Онлайн» — также в списке компьютеров и карточке компьютера.
- Интерфейс компактнее: ниже строки таблиц, меньше отступы, поля и кнопки (на сенсорных экранах элементы управления остаются крупными). В проверке версий программа и версия — в одной строке.
- Каталог программ: связанные пакеты и компоненты собраны в семейства — основной продукт и его компоненты (например, PHP и php-xml, php-gd, php-pear; Microsoft Office и Proofing Tools); универсально, по названию, без правил под отдельные программы. Семейство раскрывается в каталоге, компоненты в поиске подписаны названием семейства.
- Выбор программ прямо в каталоге: одна программа, несколько или целое семейство; выбор сохраняется при переходах между разделами; «Проверить версии» и «Отчёт по установкам» из панели выбранного.
- Проверка версий: один пункт может охватывать несколько продуктов (семейство или выбранные компоненты) — в результате и отчёте видно, какие пакеты и версии найдены и какие подходят под условие, у каждой строки — точная запись реестра и продукт каталога; в XLSX — лист «Найденные пакеты».
- Все списки — непрерывные: строки подгружаются при прокрутке, большие списки виртуализированы; поиск, фильтры и сортировка — на сервере по всему набору; при возврате из карточки сохраняются фильтры и место в списке.
- Компьютеры по щелчку на числе компьютеров или на версии открываются в боковой панели рядом с местом щелчка (компьютер, IP, онлайн, версия, ОС, группа, подключение к KSC); «Назад» из карточки компьютера возвращает к панели. Щелчок по показателю или проблеме прокручивает к списку с результатом.

### Исправлено

- Ошибки поиска в каталоге (Base DN не найден, ответ-ссылка на другой сервер, нет прав) выдавались как «Неверный логин или пароль».
- Отключены переходы по ссылкам (referrals): библиотека LDAP могла повторять поиск на другом сервере с учётными данными сервисной записи, в том числе без TLS.
- Пользователь другого домена с тем же именем мог занять запись уже существующего пользователя KAV Checker; совпадение имени с локальной учётной записью приводило к ошибке входа.
- Фильтр пользователей в стиле 0.1.0 с подстановкой `{login}` не находил пользователей.
- Списки компьютеров продукта и выбранных записей реестра заново читали KSC при каждой странице; теперь набор строится один раз и кэшируется.

### Обновление с 0.2.1

- Миграция `0004_catalog_families` добавляет в каталог поля семейств; каталоги источников перестраиваются после обновления автоматически (обычно до минуты). Данные KSC не затрагиваются.
- Интерфейс использует библиотеку `@tanstack/react-virtual` (виртуализация строк); при сборке через зеркало npm она загружается вместе с остальными пакетами.

## [0.2.1] — 2026-10-24

Интерфейс по итогам аудита 0.2.0: быстрее найти нужное и получить отчёт; данные и совместимость с 0.2.0 не меняются, миграций нет.

- Поиск в верхней панели (`/` или Ctrl+K): компьютер или программа текущего источника — за одно действие.
- Проверка версий проще: на виду программа и версия, новейшая версия из каталога подставляется щелчком; целевая версия, охват компьютеров и группа — в дополнительных настройках.
- Главная: состояние источника строкой под заголовком, первым идёт блок «Защита и угрозы».
- Источники KSC: в форме сначала сервер, база и учётная запись; шифрование, тайм-ауты и выключение — в «Дополнительно»; основное действие — «Сохранить и проверить».
- Единый вид: полоса загрузки над таблицей при обновлении данных, плавное раскрытие блоков и смена страниц, уведомления справа внизу, стрелка у показателей, которые открывают список, движение без отскоков; имена компьютеров и угроз в таблицах не переносятся; группа «Администрирование» в меню сворачивается; у «Каталога программ» своя пиктограмма; кнопки в строках таблиц — одного спокойного вида.

### Исправлено

- Каталог программ показывал неверное число скрытых компьютеров (сумму по программам).
- В карточке компьютера была неверная подпись «Время — UTC»: время показано в часовом поясе пользователя.
- Спектры версий и активности не растягивались на всю ширину карточки.
- Не было видно фокуса клавиатуры на показателях-фильтрах и строках «Проблемы защиты».
- Склонение в строке о скрытых компьютерах («Скрыто 3 компьютера»).
- Во время пересборки каталога показывался ход прошлой сборки («обновляется: готово»).
- Уведомление о запуске проверки или отчёта пропадало: страница отчёта открывалась раньше, чем оно появлялось.
- Тёмная тема: уведомления, панель выбранных строк и плитка пользователя сливались с фоном.
- Склонение в панели выбранных строк («2 версии выбраны»).

## [0.2.0] — 2026-10-24

- Каталог программ: записи реестра KSC автоматически объединяются в продукты и ветки (Google Chrome, Firefox, Java, PHP, Python, OpenSSL и другие), с производителями, версиями и числом компьютеров; ошибочную группировку можно исправить вручную.
- Проверка версий: выберите программу и версию, ниже которой она устарела, — получите компьютеры и XLSX. Несколько программ и несколько серверов KSC в одной проверке; исключение версий и веток; целевая версия; проверку можно сохранить и запускать повторно.
- Сравнение версий учитывает тип продукта: пакеты Linux, программы Windows, нестандартная нумерация Java и Python.
- Раздел «Уязвимости» начинается с самых проблемных компьютеров; есть вид по уязвимым программам и карточка компьютера с CVE, KB и наличием исправления.
- Давно не подключавшиеся компьютеры скрыты в рабочих разделах (по умолчанию — неактивные дольше 30 суток), их можно показать одной кнопкой. Порог 7 суток из 0.1.0 заменён на 30.
- Выбранный источник KSC запоминается для каждого пользователя.
- Раздел «Состояние защиты»: компьютеры без антивируса, с неработающей защитой, устаревшими базами, невылеченными объектами, истёкшей лицензией, без свежей полной проверки и ожидающие перезагрузки; пороги баз и проверки выбираются на странице; версии Kaspersky Endpoint Security и Агента администрирования по числу компьютеров с переходом к списку; причины статуса KSC.
- Раздел «События безопасности»: обнаружения, невылеченные объекты, обработанные угрозы и сетевые атаки за сутки, 7 или 30 суток; динамика, компьютеры и угрозы с наибольшим числом событий, журнал обнаружений с поиском по компьютеру, угрозе, объекту и пользователю.
- Карточка компьютера: проблемы защиты в заголовке, вкладки «Установленное ПО», «Уязвимости» и «События безопасности».
- Главная: блок «Защита и угрозы» и частые задачи аудита.
- LDAP: несколько подключений (домены) с выбором основного, вход как `EXAMPLE\user` или `user@example.local`; загрузка корневых и промежуточных сертификатов ЦС (PEM, DER, текст) с проверкой срока и отказом принять закрытый ключ; доступ по группам каталога: группа → роль и источники KSC; поиск групп в каталоге; пошаговая диагностика (DNS, TCP, TLS, цепочка сертификатов, вход сервисной записи, поиск пользователя, группы) и проверка, какой доступ получит пользователь. Настройки LDAP из 0.1.0 переносятся автоматически.
- Второй фактор (TOTP, приложения-аутентификаторы) с резервными кодами; политика: отключён, по желанию, обязателен администраторам, всем или группам каталога; администратор может сбросить второй фактор пользователя.
- Работа за reverse proxy по HTTP и HTTPS: флаг Secure у cookie включается сам, когда адрес приложения — https:// (`COOKIE_SECURE=auto`).
- Обновления: проверки перед обновлением (место на диске, доступ к GitHub и реестрам, внутренняя база, возможность отката) — кнопкой и перед каждым обновлением; приложение останавливается на время резервной копии и миграций; при ошибке миграции база возвращается к копии, неудачная сохраняется под другим именем, код и образы — к прежней версии; отчёт о последнем обновлении с выполненными действиями; восстановление копии из браузера с подтверждением; хранятся образы текущей и одной предыдущей версии.
- Зеркала npm и pip для установки и обновления без доступа к официальным реестрам (`NPM_REGISTRY`, `PIP_INDEX_URL`, `install.sh --npm-registry`); проверка контрольных сумм пакетов сохраняется; локальные правки зеркала на сервере переносятся в `.env` при обновлении.
- Состояние системы: компоненты, процессор, память, диски, размер базы, отчётов, резервных копий и образов, ошибки фоновых задач, история обновлений, безопасность. Журнал событий: произвольный период и фильтр по компоненту.

- Новый облик интерфейса: графитовое меню, единый акцент, шрифты Onest и JetBrains Mono, собственные пиктограммы.

### Обновление с 0.1.0

- Если registry.npmjs.org недоступен с сервера, перед обновлением добавьте в `.env` строку `NPM_REGISTRY=<адрес зеркала>` (например, `https://npm-mirror.gitverse.ru`): обновление собирает интерфейс локально.
- Правки файлов проекта, сделанные на сервере вручную (например, адрес зеркала в `frontend/Dockerfile`), обновление 0.1.0 откладывает в `git stash`; после обновления адрес зеркала задаётся только в `.env`.
- Порог активности 7 суток, сохранённый в 0.1.0, заменяется на 30; другое значение сохраняется.
- Подключение LDAP из 0.1.0 и его группы ролей переносятся в новые подключения и правила доступа при первом запуске.
- Откат с 0.2.0 на 0.1.0 требует восстановления копии базы, снятой перед обновлением: Администрирование → Обновления → «Резервные копии» → «Восстановить», затем «Откатить версию».
