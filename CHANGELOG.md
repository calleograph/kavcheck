## [0.6.0] — 2026-10-25

### База уязвимостей: полноценная загрузка из всех источников

- **NVD** — официальные ленты JSON 2.0 по годам (проверка SHA-256 по `.meta`, потоковый разбор, глубина истории 1…30 лет, по умолчанию 3) и лента «изменённые» для обновлений; API 2.0 — запасной канал. **OSV** — официальные архивы экосистем (по умолчанию Debian, Alpine, Red Hat, AlmaLinux, Rocky Linux ≈ 120 МБ; 43 экосистемы на выбор, размер архива показан у каждой; «вся база» — по желанию) и `modified_id.csv` для получения только изменений. **БДУ ФСТЭК** — загрузка `vulxml.zip` с сайта работает: проверка TLS по корневому и промежуточному сертификатам Минцифры, которые поставляются с приложением и применяются только к этому источнику; условный запрос (304 — без скачивания); ручная загрузка файла остаётся запасным каналом. **CISA KEV** — запасной канал: GitHub `cisagov/kev-data`.
- Каналы переключаются автоматически, все попытки (канал, результат, время, причина) видны в интерфейсе и истории. Первая загрузка и пересборка пишутся в новое поколение и подменяют действующее только после проверки; повреждённая или неполная загрузка отклоняется, действующая база сохраняется. Исправлено: первая загрузка раньше писала прямо в действующее поколение.
- Включение источника одной кнопкой («Включить все источники и загрузить») сразу ставит первую загрузку в очередь; после ошибки повтор через 30 минут; ход скачивания и этапы в интерфейсе. Скачивание потоком на том данных, проверка места до скачивания, очистка временных файлов; память не растёт с размером файла.
- Расписание и диск: у БДУ, NVD и OSV хранится одна копия данных (предыдущая удаляется после проверки), отозванные записи (NVD Rejected, OSV withdrawn) удаляются при обновлении, временные файлы убираются всегда; перед плановой загрузкой проверяется свободное место; кнопка «Обновить все сейчас», сведения о занятом месте; после перезапуска службы статус «выполняется» снимается сразу.
- Поиск: триграммные индексы PostgreSQL (миграция `0007_vdb_channels`) — поиск по 200+ тысячам уязвимостей за десятки миллисекунд; поиск уязвимостей программы **по версии** (программа в поле поиска + «Версия программы»): «затрагивает версию» или «требует уточнения».

### Обновление: надёжность

- **Обновление идёт из готовых образов (ghcr.io), а не локальной сборкой.** Причина прежнего поведения: выбор «собирать или скачивать» зависел от вида `IMAGE_REPO`, а у установки из исходников он `kavcheck` — любое обновление уходило в сборку, которой нужны Docker Hub, npm и pip. Теперь репозиторий образов определяется по `IMAGE_REGISTRY`/`GITHUB_REPO`/`origin`; локальная сборка — только по кнопке «Собрать локально» (с подтверждением), `--build`, `UPDATE_MODE=build` или `UPDATE_ALLOW_BUILD=1`, всегда с записью в журнал.
- Тайм-ауты и контроль прогресса по этапам (сеть, загрузка образов, сборка, резервная копия, миграции, запуск) и общий сторож помощника: зависшая операция останавливается вместе с дочерними процессами, блокировка снимается, причина записывается.
- Восстановление после перезагрузки или остановки помощника: метка незавершённого обновления, `scripts/recover.sh` при старте помощника и перед ручным обновлением; безопасный возврат по этапу (прежняя версия или проверенная новая), повторное обновление автоматически не запускается; статус «Выполняется» от умершего процесса снимается.
- Диагностика причин: Docker Hub, реестр образов, образов нет, npm, pip, сеть, диск, сборка, миграция, проверка здоровья, тайм-аут, прерывание — с советом в отчёте и интерфейсе. Зеркала npm/pip, настроенные на сервере, сохраняются в `.env`; проверяются фактически используемые источники; кэш npm между сборками.
- Помощник обновлений устанавливается установщиком автоматически (служба systemd с `Restart=always` без предела перезапусков), проверяется `updater.sh verify`, обновляется вместе с релизом и перезапускается на новом коде.
- В разделе «Обновления»: реальный этап, длительность, время последнего вывода, предупреждение о зависании, красная плашка при ошибке с причиной и действиями, **кнопка «Скачать журнал»** последнего обновления для диагностики (секреты маскируются).
- Образы: после успешного обновления остаются текущая и предыдущая версии; копии `.env` — последние 5. Тесты сценариев отказов — `tests/updater/run.sh` (в CI).

## [0.5.0] — 2026-10-25

### Поиск со звёздочкой

- Во всех полях поиска и фильтрах — программы, компьютеры, группы, ОС, версии, события, уязвимости (CVE, KLA, БДУ), каталог, журналы, пользователи, поиск группы в LDAP, строки отчётов — работает маска: `*` заменяет любое число символов, включая ноль. `*2026*` — CVE с 2026 в идентификаторе, `CVE-2026-*` — все за 2026 год, `*SQL*` — имена с SQL, `SRV-*` — начинаются с SRV, `*-DB` — заканчиваются на DB, `SRV-*-DB*` — несколько звёздочек. Без звёздочки поиск по части строки, как раньше; регистр не важен; пустой запрос и одна «*» — без отбора.
- Правила в одном месте на сервере (`app/search.py`): параметры запросов, экранирование `%`, `_`, `[` (в запросе это обычные символы), предел 200 знаков и 6 звёздочек (иначе ответ 422). Запросы к KSC по-прежнему только чтение, с пределом строк и тайм-аутом; маска не расширяет их нагрузку (поиск «содержит» и раньше начинался с `%`).
- В интерфейсе у полей поиска кнопка «*» с короткой подсказкой и примерами.

### База уязвимостей: оценка CVSS

- Столбцы «CVSS» (балл 0.0–10.0 и версия методики) и «Критичность» (уровень) в поиске, находках и карточке программы; сортировка по баллу (самые опасные сверху, без оценки в конце), фильтр по диапазонам и свои границы «от/до».
- Хранятся все оценки CVSS 4.0, 3.1, 3.0 и 2.0 с источником, автором оценки и датой; основная выбирается по описанному порядку (`docs/VULNDB.md`). В карточке: балл, уровень, методика, источник, вектор, дата, ссылка на первоисточник и остальные оценки. Нет достоверной оценки — «Нет данных» (не ноль).
- Прежние записи: миграция `0006_cvss_scores`, однократное преобразование баллов воркером и безопасное повторное получение отсутствующих оценок NVD без дублей.

## [0.3.0] — 2026-10-24

### Быстрые контекстные отчёты

- Отчёт из любого раздела за 2–3 действия: отметьте строки флажками (или нажмите «Отчёт по этой уязвимости») → «Сформировать отчёт» → в боковой панели сразу число затронутых компьютеров, условия, замечания о достоверности и первые строки → «Excel», «HTML для руководства» или «CSV». Источник, выбранные записи, поиск, фильтры, давность связи и «только в сети» передаются в отчёт автоматически; дополнительные условия — в раскрывающемся блоке «Дополнительно».
- «Уязвимости»: новая вкладка со списком уязвимостей KSC (KLA, CVE, опасность, программы, число компьютеров, исправление) с поиском по CVE и KLA; отчёт по одной или нескольким уязвимостям. Вкладки «Уязвимые программы» и «Компьютеры» тоже выбирают строки; карточка компьютера уязвимостей и карточка компьютера — «Подробный отчёт».
- «Компьютеры»: отчёт по выбранным устройствам — состояние, защита, установленное ПО, уязвимости (разделы выбираются). «Состояние защиты»: отчёт по текущей категории и фильтрам или по выбранным устройствам. «События безопасности»: отчёт по текущему списку (период, результат, угроза, поиск) или по выбранным событиям. «Каталог программ» и конструктор проверки версий: «Сформировать отчёт» с тем же предпросмотром.
- Правила подсчёта: уникальные компьютеры; уязвимые установки (компьютер × программа); обнаружения KSC (компьютер × уязвимость × программа); распределение по опасности — по наивысшему уровню на компьютер, сумма равна числу компьютеров. Выбор нескольких уязвимостей не удваивает компьютеры.
- «Связывался с KSC за N суток» и «в сети сейчас» — разные условия: по умолчанию учитываются устройства, связывавшиеся за период; «в сети сейчас» — отдельный фильтр, а в результатах всегда есть столбец «В сети сейчас». Если KSC не передаёт флаг присутствия, это отмечено, и фильтр не применяется молча.
- Достоверность: отчёт различает уязвимости, подтверждённые KSC, и результат проверки версий по условию пользователя; записи без привязки уязвимости к установленной версии, скрытые неактивные компьютеры и записи кластеров перечислены в замечаниях.
- Excel: листы «Сводка», основная таблица, «Компьютеры», «Программы», «Уязвимости», «Параметры»; фильтры, сортировка, закреплённый заголовок, подобранная ширина. HTML: самодостаточный документ для руководства (показатели, распределение по опасности, условия, замечания, таблицы), без внешних ресурсов и скриптов, печать и PDF средствами браузера; HTML есть и у проверки версий.
- Предпросмотр строится из того же документа, что и файлы, и кэшируется: числа в просмотре и готовом отчёте совпадают, повторное открытие не читает KSC заново. Файлы формируются фоновым воркером; готовый отчёт открывается в «Отчётах» (просмотр, повтор, скачивание XLSX, CSV, HTML).

- События безопасности: устройства, которых уже нет в KSC, показываются как «Удалённое устройство (ID …, имя неизвестно)», IP-адрес — «нет данных» (в публичном представлении KSC имя на момент события недоступно); в отчёте это отмечено и посчитано. Отчёт по событиям читает журнал одним запросом вместо постраничного чтения с повторным подсчётом: 15 тыс. событий за 30 суток на базе из 300 тыс. событий — 2,4 с вместо 16 с, повторный просмотр из кэша без запросов к SQL Server.
- HTML-отчёт при сокращении выборки (больше 3 000 строк в таблице) явно предупреждает об этом вверху документа и в панели предпросмотра; показатели сводки (компьютеры, установки, обнаружения) всегда посчитаны по полному результату, полный список — в Excel и CSV.
- Список уязвимостей на очень большой базе (650 тыс. обнаружений) загружается за 15 секунд вместо двух минут: группировка только по идентификатору уязвимости, имена и ссылки — отдельным небольшим запросом.

### Исправлено: условия проверки версий

- Отчёт должен точно соответствовать условию пользователя. Условие теперь записывается словами пользователя («Установленная версия ниже 8.4.15») и в таком виде показывается в просмотре, готовом отчёте, XLSX и CSV. Столбец «Требуемая версия» переименован в «Целевая версия» (куда обновить, например «8.4.15 или выше»): раньше его легко было принять за условие проверки. «Не ниже» заменено на «выше или равна».
- Перед выполнением условие сверяется с заданным при создании отчёта: если оператор, граница, исключения или ветки отличаются, отчёт не формируется — понятная ошибка вместо пустого отчёта по другому условию. Поля, не относящиеся к выбранному оператору, отбрасываются при приёме; диапазон с перепутанными границами отклоняется.
- Если условию не соответствует ни одна установка, отчёт объясняет почему: сколько записей реестра найдено и в каком диапазоне версий.
- Просмотр и отчёт используют один и тот же предел строк: число компьютеров в просмотре совпадает с готовым отчётом.
- Сравнение версий: предварительная версия с нулевыми частями (`5.0.0-beta`) считалась старше `5.0`.
- Проверка версий: фильтр «только устройства в сети сейчас» (по флагу KSC «видимо»), отдельный от «связывались за N суток»; в результате показано, сколько компьютеров скрыто.

## [0.2.2] — 2026-10-24

- Вход доменных пользователей по LDAPS — по короткому имени учётной записи (например, `ivan.petrov`), без `@домен` и `ДОМЕН\`: имя ищется во всех настроенных доменах. Если одно имя есть в нескольких доменах, на странице входа выбирается домен; вход в «чужой» домен исключён.
- Раздел «LDAP» переименован в «LDAPS». Проверка подключения к контроллеру домена и проверка входа пользователя разделены: «Проверка входа» проходит тот же путь, что настоящий вход (поиск в каждом домене, пароль, группы, правила, второй фактор), и показывает причину на каждом шаге.
- Точная причина неудачного входа (пользователь не найден, ошибка поиска, пароль отклонён контроллером, нет разрешённой группы) — в журналах администратора; пользователь видит общее сообщение.
- «Состояние защиты»: фильтр «Только онлайн» (включён по умолчанию) — числа проблем, списки и поиск только по устройствам, которые KSC сейчас видит в сети; колонка «Онлайн». «В сети» определяется по флагу KSC «видимо», а не по давности подключения; нет сведений — «нет данных». Статус «Онлайн» — также в списке компьютеров и карточке компьютера.
- Интерфейс компактнее: ниже строки таблиц, меньше отступы, поля и кнопки (на сенсорных экранах элементы управления остаются крупными). В проверке версий программа и версия — в одной строке.
- Каталог программ: связанные пакеты и компоненты собраны в семейства — основной продукт и его компоненты (например, PHP и php-xml, php-gd, php-pear; Microsoft Office и Proofing Tools); универсально, по названию, без правил под отдельные программы. Семейство раскрывается в каталоге, компоненты в поиске подписаны названием семейства.
- Выбор программ прямо в каталоге: одна программа, несколько или целое семейство; выбор сохраняется при переходах между разделами; «Проверить версии» и «Отчёт по установкам» из панели выбранного.
- Проверка версий: один пункт может охватывать несколько продуктов (семейство или выбранные компоненты) — в результате и отчёте видно, какие пакеты и версии найдены и какие подходят под условие, у каждой строки — точная запись реестра и продукт каталога; в XLSX — лист «Найденные пакеты».
- Все списки — непрерывные: строки подгружаются при прокрутке, большие списки виртуализированы; поиск, фильтры и сортировка — на сервере по всему набору; при возврате из карточки сохраняются фильтры и место в списке.
- Компьютеры по щелчку на числе компьютеров или на версии открываются в боковой панели рядом с местом щелчка (компьютер, IP, онлайн, версия, ОС, группа, подключение к KSC); «Назад» из карточки компьютера возвращает к панели. Щелчок по показателю или проблеме прокручивает к списку с результатом.

### Исправлено

- Ошибки поиска в каталоге (Base DN не найден, ответ-ссылка на другой сервер, нет прав) выдавались как «Неверный логин или пароль».
- Отключены переходы по ссылкам (referrals): библиотека LDAP могла повторять поиск на другом сервере с учётными данными сервисной записи, в том числе без TLS.
- Пользователь другого домена с тем же именем мог занять запись уже существующего пользователя KAV Checker; совпадение имени с локальной учётной записью приводило к ошибке входа.
- Фильтр пользователей в стиле 0.1.0 с подстановкой `{login}` не находил пользователей.
- Списки компьютеров продукта и выбранных записей реестра заново читали KSC при каждой странице; теперь набор строится один раз и кэшируется.

### Обновление с 0.2.1

- Миграция `0004_catalog_families` добавляет в каталог поля семейств; каталоги источников перестраиваются после обновления автоматически (обычно до минуты). Данные KSC не затрагиваются.
